# VIXEN Architecture Review: From Research Renderer to Undertow's Game Engine

**Scope.** This review evaluates VIXEN against a specific target: a reusable, moddable game render engine consumed as a library by *Undertow*, a deep-simulation game combining Stellaris-style grand-strategy presentation, RTS functionality, rich dialogue/UI, procedural sim-driven content, and first-class moddability. Every claim below was adversarially verified against the codebase; corrections to overstated findings are applied inline, and sub-claims that turned out to be already supported are recorded in [[#Appendix B — Refuted and Corrected Sub-Claims|Appendix B]].

Related vault docs: [[RenderGraph-System]], [[Overview]], [[Type-System]], [[capability-requirement-matrix]], [[Production-Roadmap-2026]], [[Sprint8-Timeline-System]], [[Sprint6.5-Consolidation-Audit]].

---

## 1. Executive Summary

**What VIXEN is today:** a single-purpose Vulkan voxel ray-marching research renderer. One window, one swapchain, one camera, one compute-dispatch scene baked once at startup, driven by a Win32 singleton executable that hand-wires ~16 nodes and ~100 connections in C++ at compile time. Its render-graph kernel, connection system, caching layer, shader toolchain, and budget/profiling stack are genuinely sophisticated — but every one of them assumes a static, developer-authored, single-view, disposable research app.

**What the target requires:** an instantiable engine library with multiple simultaneous views, per-frame sim-driven content streaming, runtime graph mutation, text/UI compositing, many-entity rendering, recoverable errors, and a data-driven operations surface mods can drive.

**Readiness verdict:** the *bones* are unusually good — better than a typical research codebase. The NodeType/NodeInstance split, the runtime-extensible `NodeTypeRegistry`, the injected `MessageBus`, string-keyed runtime parameters, the `TypedCacher` recipe, runtime GLSL compilation with SPIRV reflection, the `CapabilityGraph`, and the calibrated frame-budget loop are all the correct shapes for a moddable game engine. But the *boundary* does not exist: no engine facade, no consumable build artifact, no offscreen render targets, no data-driven wiring, no text rendering, and a process-fatal error model. Across two adversarial verification rounds covering all 53 gap claims (30 in round 1; the 23 deferred majors in round 2, same date), the gap analysis found **10 confirmed blockers, 11 confirmed majors, and 32 partially-accurate gaps** (most partials narrower than originally claimed — though several came back *worse*: cache identity and the per-frame dynamic-content gap in §5.1, plus the cornell-fallback and CleanupByTag findings re-flagged in Appendix B; in most cases the missing piece is *wiring and a boundary*, not a from-scratch capability). Zero claims were fully refuted, but ~two dozen sub-claims were found already supported (Appendix B).

### The five decisions that matter most

1. **Reverse the documented anti-plugin positioning before Sprint 8 ships.** ✅ **ACTIONED 2026-06-13** — the Sprint 8 plan is re-scoped: the "not plugin hosts" positioning is reversed and a *Public Mod-API Requirements* section (R1 string addressing, R2 Result-not-throw, R3 generational handles, R4 connection records, R5 thin boundary) now constrains the Phase 4–5 machinery. The Layer-0 error-model prerequisite (decision #4 / AR#1) is also done (phases 1–3 merged). See [[Sprint8-Timeline-System]] § *Framework Positioning* + § *Public Mod-API Requirements*. — [[Sprint8-Timeline-System]] (with its feature proposal, [[timeline-execution-system]]) specifies ~80% of the runtime-mutation machinery a mod API needs (GraphSerializer JSON round-trip, GraphEditorNode frame-boundary edit queue, ValidationNode dry-run, SnapshotNode rollback) — and the *same document* declares VIXEN targets "self-contained applications (not plugin hosts)". If Sprint 8 is implemented against internal-tool requirements (raw handles, throw-on-error, no string addressing), the moddability pillar must be retrofitted later at far higher cost. Specify Sprint 8 against public-API requirements now; the implementation cost is the same.
2. **Extract an instantiable `EngineContext` and sever the build-layering leaks.** `VulkanGraphApplication` already owns exactly the right member set (`NodeTypeRegistry`, `MessageBus`, `RenderGraph`, `CalibrationStore` — all `unique_ptr`s); lifting it is restructuring along existing seams, not a rewrite. The harder, purely mechanical half: three core libraries PUBLIC-include `application/main/include`, ~32 non-test library files (38 counting `RenderGraph/tests/`) `#include "Headers.h"`, no `install(EXPORT)`/`VIXENConfig.cmake` exists anywhere. Undertow physically cannot link VIXEN today.
3. **Make the render target an abstraction, not the swapchain.** Every recording node hard-requires `SwapChainPublicVariables*`. Minimap, portraits, picking ID-buffers, post-processing, and multi-view — essentially the entire grand-strategy presentation layer — hang off this single change. The lower layers (allocators, descriptor binding of arbitrary image views, the DepthBufferNode precedent) already support it; only the producer node and slot migration are missing.
4. **Replace the process-fatal error model with the result types that already exist.** `std::exit(1)` on duplicate connection, `exit(-1)` on zero surface extent, throw-to-main, `RenderFrame()` unconditionally returning `VK_SUCCESS`. `std::expected`-based `VulkanResult`/`VulkanStatus` and `ConnectionResult` already exist in-tree; this is mechanical substitution at ~a dozen audited call sites and is prerequisite to every mod-facing feature.
5. **Adopt chunked multi-volume worlds instead of widening the single octree.** The voxel stack's scale ceilings (15-bit child pointers silently truncated, single `OctreeBlock`, 1024 bricks/axis, one entity per Morton cell) are sized for a Cornell box. Composing many bounded volumes — each inside current limits — aligns with the streaming chunk granularity the sim needs, reuses the dormant `VolumeGrid`/`VoxelVolumeArchetype` vocabulary, and demotes far-pointer support from prerequisite to optimization. This decision also forces the terrain question (voxel vs heightmap) early.

**Roadmap reality check:** [[Production-Roadmap-2026]] allocates Q2 2026 through Q1 2027 (Sprints 7–14, 936h — round 2 corrected the earlier ~1,100h figure) to voxel physics, timeline, auto-sync, multi-GPU, soft body, procedural generation, and VR; none of it is presentation or embedding work, though Sprint 8's 144h timeline slot is the mod-API seed. Adopting the Undertow target is a re-plan, not an addition (§8).

## 2. Target Vision & Derived Requirements

The vision decomposes into six capability domains. Each row is a concrete renderer requirement the gap analysis (§5) is scored against.

### 2.1 Procedural sim-driven rendering
- Sim-to-render change bridge: host sim owns world state, mutates it every tick; renderer consumes deltas (dirty regions, entity events) and updates GPU data incrementally — never whole-scene rebake.
- Incremental spatial-structure updates: localized SVO hierarchy patching, per-brick recompression, partial GPU re-upload of dirtied ranges.
- Streaming/out-of-core world: chunk-grained load/unload, LRU eviction under budget pressure, camera/zoom-driven priority and prefetch; world size exceeds VRAM and RAM.
- Background asset/chunk creation off the frame thread, with results re-entering at safe points.
- Per-frame upload machinery: prioritized, throttled, cancellable batched uploads of buffers **and** images, ideally on a dedicated transfer queue.
- Runtime structural graph growth ("richer over time"): frame-boundary graph mutation with validation and rollback.
- Externally-owned world data: renderer consumes a sim-owned ECS world instead of constructing voxel content internally.
- Procedural cache identity: generator id + version + params + chunk coordinate; individually invalidatable.
- Scale headroom: coordinate ranges, pointer widths, block counts beyond research scenes.
- Non-blocking rebuilds (double-buffered structure swap) and budget-integrated churn scheduling.

### 2.2 RTS functionality
- Instanced/indirect many-entity rendering (thousands of units, per-instance data, batching, culling).
- Picking/selection: GPU ID-buffer with async readback + CPU ray/box fallback; click and drag-rect; results as host events.
- RTS camera: ortho + perspective, pan/zoom-to-cursor/edge-scroll, host-injectable pose, queryable screen↔world transforms.
- Terrain (voxel or heightmap) with LOD, overlay channels, incremental updates.
- Fog-of-war: persistent visibility mask updated by compute from sim data, sampled by downstream passes, explored-vs-visible state.
- Minimap and multiple simultaneous views (camera + render target + pass chain per view).
- Per-frame sim→renderer entity data flow with dirty tracking.
- Render-to-texture as a first-class graph concept; frame architecture scaling to dozens of passes with graph-managed sync and conditional pass execution.

### 2.3 Grand-strategy presentation
- Multi-scale strategic camera (4+ orders of magnitude zoom, precision strategy).
- Zoom-dependent **representation** switching (3D → impostor → icon → aggregate) with hysteresis — distinct from geometric LOD.
- World-anchored text/icon rendering at thousands-of-labels scale, with declutter.
- Togglable map-mode overlay passes, alpha-composited, switchable at runtime.
- Massed-entity visualization (10k–1M markers via instanced/indirect draws with GPU culling).
- Data-driven presentation definitions (icon sets, zoom bands, map modes from files).
- Game-appropriate presentation policy: runtime vsync/present-mode control, stable pacing.

### 2.4 Dialogue & UI
- Text/font subsystem: loading, glyph atlas (raster/MSDF), shaping/layout, dynamic per-frame strings.
- Alpha-blended 2D UI pass composited over 3D (blend pipelines, LoadOp::Load, per-draw scissor, draw-order sort).
- Per-frame dynamic geometry: rewritten vertex/index streams, hundreds of draws with per-draw texture binding.
- Runtime image/portrait pipeline (string-addressed textures, hot swap), offscreen portrait scenes.
- UI input routing: text input/IME, UI-first hit testing with consume semantics and subscriber priority, focus/capture.
- ImGui-class integration seam; sRGB-correct compositing; DPI awareness.

### 2.5 Moddability & engine-ops API
- Stable engine facade with host-owned frame loop; recoverable uniform errors at every entry point.
- Generation-checked opaque handles crossing DLL/script boundaries.
- Data-driven graph/scene descriptions (JSON), runtime mutation with validation/preview/rollback.
- Command/request-response surface distinct from notifications; stable string/hash event identity.
- Script-binding-ready boundary (handles + strings + POD variant only); mod content pipeline (VFS, namespaced identity, runtime shader compilation as first-class path).
- Introspection/enumeration of types, instances, connections, parameters, capabilities, caches.
- Sandboxing/quotas per mod; versioned capability negotiation; semver'd public headers and licensing clarity.

### 2.6 Engine–app boundary
- Instantiable engine context (no process singletons/statics); inverted frame-loop control.
- Engine-created **and** host-supplied window/surface; platform-abstracted windowing/input.
- Multi-graph/multi-view lifecycle under one device; clean teardown/re-init within a process.
- Consumable build artifact: `install()+export()`, `VIXENConfig.cmake`, zero include leaks, self-provisioned dependencies.
- Headless/offscreen init path for CI and tooling; host-injectable services (bus ✅, logger sink, cache root, config); embedding documentation.

## 3. Current Architecture Map

Maturity scale: 1 = sketch, 2 = prototype, 3 = works-for-research, 4 = solid, 5 = production.

### 3.1 RenderGraph-Core — maturity 3
**Purpose.** Orchestration kernel: NodeType blueprints instantiated as NodeInstances, wired into a `GraphTopology` DAG, compiled through a multi-phase pipeline, executed per frame with event-driven dirty-node recompilation, ordered teardown (`CleanupStack` + `ResourceDependencyTracker`), and a calibrated task-profiling/frame-budget loop (`TaskProfileRegistry` → `TimelineCapacityTracker`).
**Role in target.** The spine. The DAG model, lifecycle hooks, and dirty-recompile machinery survive; the single-view/static-topology/fatal-error assumptions do not.
**Key extensibility points.** `NodeTypeRegistry::Register<T>` (the primary plugin seam — proven from outside the library); `GraphLifecycleHooks` (6 graph + 8 node phases); `IGraphCompilable::GraphCompileSetup`; `MessageBus` subscriptions; `RegisterExternalCleanup`; node tags; `NodeParameterManager` (string-keyed runtime `SetParameter` — already mod-call-shaped); `TaskProfileRegistry::RegisterFactory`.
**Hard liabilities.** Graph frozen after first frame (contract-only, not enforced); `RemoveNode` invalidates handles by index shift; core `#include`s concrete nodes and PUBLIC-links SVO; cache path hardcoded to relative `"cache"`; `AllocateResources()` is an empty stub; `std::exit(1)` on duplicate connection; loop ticking dead in the `RenderFrame()` path.
**Key files.** `libraries/RenderGraph/include/Core/RenderGraph.h`, `src/Core/RenderGraph.cpp`, `include/Core/NodeTypeRegistry.h`, `include/Core/GraphLifecycleHooks.h`, `include/Core/TaskProfileRegistry.h`, `include/Core/CalibrationStore.h`, `libraries/RenderGraph/CMakeLists.txt`.

### 3.2 RenderGraph-Connection — maturity 3
**Purpose.** Wiring layer: unified `ConnectionBatch::Connect` builds runtime `SlotInfo` from compile-time slot/binding types, selects a prioritized `ConnectionRule` (Accumulation > Direct > Variadic), executes through a 5-phase pipeline with stackable `ConnectionModifier`s (FieldExtraction, SlotRole, GroupKey, DebugTag).
**Role in target.** Internally the right shape for a mod-facing connect API — `SlotInfo` is already a runtime type-erased slot description, rules match at runtime via `CanHandle`. Needs a string/handle facade, recoverable errors, registry injection, and a persistent connection record.
**Key extensibility points.** `ConnectionRuleRegistry::RegisterRule` (open in principle; unreachable because `ConnectionBatch` hardcodes `CreateDefault()`); `ConnectionModifier` subclassing; `UnifiedConnect::ValidateConnection` standalone validation (tooling-usable).
**Hard liabilities.** No disconnect/rewire orchestration (primitives exist unwired — see Appendix B); `RegisterAll()` throws on first failure routing into `std::exit(1)`; accumulation production path incomplete (`ctx.accumulationState` set only by tests); resolved connections persist only bare `GraphEdge` endpoints — rule/modifiers/debugTag discarded, and accumulation connections leave no edge at all [round 2]; test scaffolding leaks into production connection semantics — `IsValidNodePtr` (pointer > 0x10000) sentinel checks in all three rules, a `skipDependencyRegistration` flag, and `reinterpret_cast` 0x1/0x2 sentinels in `ValidateConnection` — which matters because §5.5/Phase 5 elevate `ValidateConnection` to the mandatory mod-wiring gate (strip the sentinels first).
**Key files.** `libraries/RenderGraph/include/Core/TypedConnection.h`, `include/Connection/ConnectionPipeline.h`, `include/Connection/ConnectionRuleRegistry.h`, `include/Data/Core/SlotInfo.h`, `src/Connection/Rules/DirectConnectionRule.cpp`.

### 3.3 RenderGraph-Nodes — maturity 3
**Purpose.** ~34 concrete node types wrapping every Vulkan stage: bootstrap (Instance/Window/Device/SwapChain/Present), resources, pipelines (with reflection-driven descriptor/push-constant gatherers), command recording (GeometryRender, ComputeDispatch, MultiDispatch, TraceRays), and plumbing (Camera, Input, Constant, LoopBridge). Exactly three techniques end-to-end: compute ray-march to swapchain, single-draw forward raster, hardware RT over voxel AABBs.
**Role in target.** The node *recipe* (`TypedNode<Config>` + constexpr NodeConfig + `Register<T>`) is the extension mechanism every new game feature rides. The node *inventory* covers almost none of the game's needs (no RTT, UI, text, instancing, picking, streaming nodes).
**Key extensibility points.** Runtime `Register<T>` from host code (proven: `ConstantNodeType` in `application/main/source/VulkanGraphApplication.cpp`, RT nodes in `libraries/Profiler/src/BenchmarkRunner.cpp`); `ConstantNode` host-data injection with cleanup callbacks; reflection-driven variadic gatherers; string-keyed parameters; `SlotRole::Debug` auto-routing.
**Hard liabilities.** Every recording node hard-requires `SwapChainPublicVariables*`; sync is hand-routed per node (15–17 input slots on dispatch nodes); `GeometryRenderNode` records exactly one draw from compile-time-static counts; alpha blending hardcoded off (`GraphicsPipelineNode.cpp:456`); content nodes bake once at Compile.
**Key files.** `libraries/RenderGraph/include/Core/TypedNodeInstance.h`, `include/Core/VariadicTypedNode.h`, `include/Data/Nodes/*.h` (configs), `src/Nodes/GeometryRenderNode.cpp`, `src/Nodes/ComputeDispatchNode.cpp`, `include/Nodes/ConstantNode.h`.

### 3.4 VulkanResources — maturity 2
**Purpose.** Vulkan bootstrap: instance/device creation, Win32 surface + swapchain, string-keyed `CapabilityGraph` gating extensions/layers/features, service-locator facade on `VulkanDevice` (uploader/updater/budget/query manager injected by `DeviceNode`).
**Role in target.** `CapabilityGraph` is the credible foundation of a mod-manifest capability query surface (`HasCapability("RTXSupport")` is exactly the right shape). Everything else needs a platform seam, multi-queue, presentation policy, and per-instance state.
**Key extensibility points.** `CapabilityGraph::RegisterCapability` + composite capabilities; `VulkanDevice` service injection setters; abstract `TextureLoader` (GLI/STB backends); embryonic `std::expected`-based `VulkanResult`/`VulkanStatus` in `include/error/VulkanError.h`.
**Hard liabilities.** Win32-only `CreateSurface(HWND, HINSTANCE)`; STATIC class-level capability vectors (one device per process); single graphics queue, "assume present support"; benchmark presentation policy (IMMEDIATE-first, no vsync API, no `oldSwapchain`, no OUT_OF_DATE recovery); PUBLIC-includes `application/main/include` and uses app `Headers.h` as its PCH; `exit(-1)` on zero surface extent. A GLFW port + self-provisioning Vulkan SDK is already **merged into `main`** (merge f4e2fbc, "Windows behavior verified unchanged"; 89e3ed5 "builds clean on Windows") — the sprint-6 working branch simply predates it [corrected round 2; previously recorded here as unmerged/unverified].
**Key files.** `libraries/VulkanResources/include/VulkanDevice.h`, `include/CapabilityGraph.h`, `src/VulkanSwapChain.cpp`, `include/error/VulkanError.h`, `libraries/VulkanResources/CMakeLists.txt`.

### 3.5 CashSystem — maturity 3
**Purpose.** Resource caching: singleton `MainCacher` with per-GPU registries + a global registry, ~15 `TypedCacher` subclasses (shaders, pipelines, layouts, descriptors, textures, meshes, voxel scenes, AS/TLAS), hash-keyed `GetOrCreate`, disk persistence with manifests and a session-lock corruption guard.
**Role in target.** The chassis for every future asset/chunk cache — the `TypedCacher` recipe (Create() + ComputeKey()) is proven 15 times. Needs: instance-not-singleton, string/GUID identity, eviction, async creation, host-configurable root.
**Key extensibility points.** `RegisterCacher<>` open runtime registry (9+ node call sites); `m_nameToFactory` string-keyed factory map (proves string identity works); per-cacher serializer virtuals; `DeviceInvalidationEvent` bus channel; `RenderGraph(MainCacher*)` injection seam (currently illusory — internals call `Instance()` directly).
**Hard liabilities.** Meyers singleton; cache root literal `"cache"` in five sites (`MainCacher.h:191`; `RenderGraph.cpp:305/317/358/1048`) [round 2]; persistence lifecycle lives in `RenderGraph.cpp`, not here; `TypedCacher` pending-future wait **holds the lock** (guaranteed deadlock under concurrent same-key requests); zero eviction vocabulary; session-lock recovery wipes `cache/devices` wholesale; keys are unpublishable typeid+struct hashes; custom generators silently alias to `SceneType::Custom` and regress to the cornell generator.
**Key files.** `libraries/CashSystem/include/MainCacher.h`, `include/TypedCacher.h`, `include/VoxelSceneCacher.h`, `src/VoxelSceneCacher.cpp`, `src/main_cacher.cpp`.

### 3.6 ShaderManagement — maturity 3
**Purpose.** Shader toolchain: GLSL→SPIR-V via glslang, SPIRV-Reflect into a rich runtime model (`SpirvReflectionData`), generated "SDI" constexpr C++ headers, content-hash disk cache, include-resolving preprocessor, async build pool, hot-reload-oriented `ShaderLibrary` (instantiated nowhere), build-time CLI.
**Role in target.** Paradoxically both the closest thing to a moddable surface (runtime compile + reflect of raw GLSL strings works today) and a blocker (the engine's actual consumption path is compile-time SDI headers included by C++ source). The pragmatic move: promote the reflection-driven runtime path (~80% built) to first-class; demote SDI headers to an internal optimization.
**Key extensibility points.** `ShaderBundleBuilder::AddStage(stage, sourceString)` + per-stage defines + include paths; `ShaderLibraryNode::RegisterShaderBuilder` lambda seam; EventBus shader lifecycle messages (types 200–299); `SdiDiscoveryScanner` + LAYOUT_HASH runtime discovery embryo; data-driven `shaders.json` build tooling.
**Hard liabilities.** SDI chicken-and-egg (app includes runtime-generated headers); hot reload complete-looking but disconnected end-to-end; spec-constant reflection is a stub; no shader variant matrix (the built `SetStageDefines` mechanism has zero callers — the app A/Bs whole files via `#if USE_COMPRESSED_SHADER`); 64-bit FNV "SHA256" naming; no VFS for mod-shipped sources.
**Key files.** `libraries/ShaderManagement/include/ShaderBundleBuilder.h`, `include/SpirvReflectionData.h`, `include/ShaderLibrary.h` (dead), `include/SdiDiscoveryScanner.h`, `libraries/RenderGraph/include/Nodes/ShaderLibraryNode.h`.

### 3.7 Voxel-Stack (SVO + VoxelData + VoxelComponents) — maturity 3
**Purpose.** CPU-side Laine-Karras ESVO acting as a spatial index ("SVO-as-view") over voxel entities in Gaia ECS; 8³ bricks via zero-copy `EntityBrickView`; `rebuild()` bins, Morton-sorts, builds descriptors bottom-up, DXT1-compresses for GPU. VoxelData adds a runtime attribute schema (`AttributeRegistry`, deprecated in the live path); VoxelComponents defines the compile-time ECS vocabulary.
**Role in target.** Voxel terrain/world candidate — if the terrain decision lands on voxels. The SVO-as-view architecture is right for sim-owned worlds; the implementation is a one-shot bake with a façade incremental API.
**Key extensibility points.** `ISVOStructure` abstraction (one implementation); `AttributeRegistry` runtime schema with observers (the right idea, sidelined); `setKeyPredicate`; `BuildParams` knobs; `ISVOStreamingManager` contract (interface-only); `updateBlock()/removeBlock()` + `m_renderLock` (partial — see §5.1).
**Hard liabilities.** `updateBlock` never patches `ChildDescriptors` or recompresses (`SVORebuild.cpp:738-792`, contradicting its own header doc); streaming has zero implementation; serialization stubs; 15-bit childPointer silent truncation (`SVORebuild.cpp:584`), farBit always 0, single `OctreeBlock`, 1024 bricks/axis; GPU contract implicit (cacher memcpys internals; shader layout hand-synced).
**Key files.** `libraries/SVO/include/LaineKarrasOctree.h`, `src/SVORebuild.cpp`, `src/SVOTraversal.cpp`, `include/SVOStreaming.h`, `libraries/VoxelData/include/AttributeRegistry.h`, `libraries/VoxelComponents/include/VoxelComponents.h`.

### 3.8 Gaia-ECS (GaiaVoxelWorld + GaiaArchetypes) — maturity 2
**Purpose.** Gaia ECS wrapper as the "single source of truth" voxel store: entity-per-voxel keyed by MortonKey, batch creation, Morton-hash point lookup, `queryRegion` AABB gather, brick loaders, chunk grouping. GaiaArchetypes (string-keyed `ArchetypeRegistry`/`EntityFactory`, relationship hooks) is linked by nothing but its own tests.
**Role in target.** The substrate a sim-owned world would extend — but its component vocabulary is voxel-only, the component set is compile-time-closed, and the production consumer (`VoxelSceneCacher`) constructs the world internally so an external sim cannot share it.
**Key extensibility points.** X-macro component registry (compile-time); `getWorld()` raw escape hatch; `ArchetypeRegistry` + `EntityFactory::create(string)` (the closest seam to data-driven entity definitions, unconsumed); relationship observers; `hasComponent(entity, "name")`.
**Hard liabilities.** No change events on create/destroy/modify; one entity per Morton cell with silent overwrite (orphans the prior entity); O(N) region scans beyond the point hash; `VoxelInjectionQueue` async pipeline implemented but racy and unused; no serialization; two divergent archetype systems.
**Key files.** `libraries/GaiaVoxelWorld/include/GaiaVoxelWorld.h`, `src/GaiaVoxelWorld.cpp`, `include/EntityBrickView.h`, `include/VoxelInjectionQueue.h`, `libraries/GaiaArchetypes/include/ArchetypeBuilder.h`.

### 3.9 ResourceManagement — maturity 3
**Purpose.** Memory budgeting and transfer: `IMemoryAllocator` backends (VMA built but unwired; DirectAllocator in production), per-type and string-keyed budgets with strict/soft limits, `StagingBufferPool`, `BatchedUploader` (timeline-semaphore completion), `BatchedUpdater` (polymorphic per-frame command recording), `DeferredDestructionQueue`, host-side streaming half (`HostBudgetManager`/`BudgetBridge` — built, consumed by nothing).
**Role in target.** The transport layer for all streaming/dynamic content. Needs: image uploads, priorities/throttling, eviction policy on top of tracking, the VMA path wired (DirectAllocator's one-allocation-per-resource will hit `maxMemoryAllocationCount` ≈ 4096 at game scale), and event publication.
**Key extensibility points.** `IMemoryAllocator` drop-in backends; string-keyed custom budgets (the `StagingQuota` pattern — the natural per-mod quota seam); `UpdateRequestBase::Record()` subclassing; `DeferredDestructionQueue::AddGeneric`; frame-event bus subscription.
**Hard liabilities.** Budgets track-and-warn (or strict-fail) but never reclaim; `BatchedUploader` is buffer-only; documented backpressure is fictional (fail-fast everywhere); `BufferWriteRequest` exists only in a comment; `VulkanDevice::RecordUpdates` has zero callers — the per-frame update path is dead-ended in production; raw `void*` handles. Budget detection is a one-shot heap-size sum at startup — no `VK_EXT_memory_budget` integration, so the budget never re-detects and ignores other applications' VRAM use; and no defragmentation story is surfaced (VMA provides one) — long grand-strategy sessions with constant procedural churn will fragment.
**Key files.** `libraries/ResourceManagement/include/Memory/BatchedUploader.h`, `include/Updates/BatchedUpdater.h`, `include/Memory/DeviceBudgetManager.h`, `include/Memory/ResourceBudgetManager.h`, `include/Lifetime/DeferredDestruction.h`.

### 3.10 Infra (EventBus + Core + logger) — maturity 3
**Purpose.** `MessageBus`: mutex-protected pub/sub with pre-allocated queue, frame-synchronous dispatch at `ProcessMessages()` safe points, type + category filtering, RAII subscriptions, `WorkerThreadBridge` for async re-entry. Core: only `MortonCode64` + Vulkan forward decls. logger: in-memory hierarchical tree.
**Role in target.** EventBus is the architectural seed of the engine-ops spine — the only dependency-free, injected, cross-library channel in VIXEN. Today it is *observable, not operable*: outward notifications with no command vocabulary, `__COUNTER__`-derived type IDs that cannot cross a build/script boundary, closed category enum, no priorities/consume semantics, dispatch holds the subscription mutex across handlers (re-entrancy deadlock).
**Key extensibility points.** New event structs via `AUTO_MESSAGE_TYPE()` without touching bus code (the one genuinely open seam engine-wide); category bitmask subscriptions; `SubscribeAll` (tracing/replay tooling); constructor-injected bus; `WorkerThreadBridge<T>`.
**Hard liabilities.** Build-fragile event identity; Win32 virtual-key codes as the engine-wide input vocabulary; `void*` payloads on device events; Logger not thread-safe, unbounded, sinkless; Core lacks an actual core layer (no handles, config/CVar, time service, platform abstraction).
**Key files.** `libraries/EventBus/include/MessageBus.h`, `include/Message.h`, `include/InputEvents.h`, `include/WorkerThreadBridge.h`, `libraries/Core/include/MortonEncoding.h`, `libraries/logger/Logger.h`.

### 3.11 Profiler — maturity 3
**Purpose.** Offline benchmark harness: `BenchmarkRunner::RunSuite` owns a full Vulkan lifecycle independently of the main app (instance/device/graph per test, windowed or headless), JSON-driven test matrices, CSV/JSON/PNG/ZIP export, NVML/VK_EXT_memory_budget metrics. A parallel `ProfilerSystem` singleton hook stack is dormant in the windowed path.
**Role in target.** Two things transfer: (1) `BenchmarkRunner` is the **working reference implementation of engine bring-up outside the main app** — the factoring target for `EngineContext`; (2) the JSON suite config is the most data-driven surface in the repo — the template for `EngineConfig`. The metrics stack itself is research-specific (closed `FrameMetrics` struct, fence-stalled readbacks, no HUD/live feed, two uncoordinated profiling systems vs the Sprint 6.5 `ITaskProfile` stack).
**Key files.** `libraries/Profiler/src/BenchmarkRunner.cpp`, `src/BenchmarkGraphFactory.cpp`, `include/Profiler/BenchmarkConfig.h`, `application/benchmark/benchmark_config.json`.

### 3.12 Application-Layer — maturity 2
**Purpose.** The sole interactive consumer: Win32 singleton executable owning `main()`, the blocking Update/Render loop with `PeekMessageW` pump, instance creation, 30 node-type registrations, and a ~777-line hand-wired `BuildRenderGraph()` (compute ray-march, 128³ Cornell box). Every configuration decision is a C++ literal; `argv` ignored.
**Role in target.** Becomes a thin reference host once `EngineContext` is extracted. Its wiring vocabulary (uniform `Connect(src, slot, dst, slot)` sequences, `SetParameter`, `GetInstanceByName`) is mechanically translatable into the future graph file format — an immediate test corpus.
**Key files.** `application/main/source/VulkanGraphApplication.cpp`, `include/VulkanGraphApplication.h`, `source/main.cpp`, `include/Headers.h` (the layering-leak nexus).

### 3.13 Docs-Roadmap — maturity 4

## 4. Architecture Strengths

What to build on — and *why* each survives the transition.

1. **NodeType/NodeInstance + runtime-open `NodeTypeRegistry`.** Third-party node injection is not theoretical: the app registers `ConstantNodeType`, the Profiler registers the RT node set, both from outside the library. Every new game feature in this review (RenderTargetNode, InstancedDrawNode, TextBatchNode, FogOfWarNode, StreamingBufferNode, PickingReadbackNode) rides this exact seam with zero core changes. This is the plugin mechanism; it just lacks a data-driven front end.
2. **String-keyed runtime parameters + name-addressable instances.** `GetInstanceByName` + `SetParameter(name, ParamTypeValue)` over a macro-generated POD-ish variant is already the shape of a mod-facing "set parameter" operation. The seed of the engine-ops API exists and works today.
3. **Injected, dependency-free EventBus.** App-owned, constructor-injected everywhere, open to new event types without bus edits, with `SubscribeAll` for tooling and `WorkerThreadBridge` for async re-entry. Wrong identities (compile-time `__COUNTER__`) and no command layer — but the *topology* (one spine all subsystems already speak) is exactly what an engine-ops surface federates around.
4. **Event-driven dirty recompilation, proven in production.** `MarkNeedsRecompile` → `RecompileDirtyNodes` (Cleanup→Setup→Compile with dependent cascade via `CleanupStack`) already survives swapchain resize. This is the kernel of incremental structural recompile — Sprint 8's edit queue lands on a working foundation, and zoom-LOD parameter switching can be prototyped on it *today*.
5. **Runtime shader compilation + SPIRV reflection as a working path.** `ShaderBundleBuilder` compiles raw GLSL strings at runtime; descriptor/push-constant gatherer nodes wire bindings from reflection, not hardcoded layouts. A mod-shipped shader is compilable today without engine recompilation. This is the single most mod-ready capability in the codebase — it merely is not the default consumption path.
6. **`TypedCacher` recipe (15 proven examples).** Subclass + `Create()` + `ComputeKey()` yields a thread-safe, persisted, budget-tracked cache. GlyphAtlasCacher, IconAtlasCacher, VoxelChunkCacher are all "the 16th example", not new architecture. The `m_nameToFactory` string map proves string-keyed instantiation already works in this layer.
7. **`CapabilityGraph` string-keyed runtime capability queries.** `HasCapability("RTXSupport")` with composite capabilities is precisely the query a mod manifest or settings UI consumes. Needs per-instance state, documentation, and versioning — but the concept is implemented and consumed (Profiler's `requiredCapabilities` gating).
8. **Calibrated frame-budget loop (Sprint 6/6.5).** `ITaskProfile` cost learning + per-GPU `CalibrationStore` persistence + `TimelineCapacityTracker` pressure adjustment is exactly the vocabulary needed to throttle streaming/rebuild/upload churn so sim-driven content degrades gracefully instead of spiking frames. Few engines at this stage have this; it directly serves the deep-sim pillar.
9. **`BenchmarkRunner` as a second host.** A full, working engine bring-up (instance, device, registry, bus, graph, frame loop, teardown) outside the main application, driven by JSON config, with windowed and headless modes and a pluggable graph factory. It refutes "the engine cannot be re-hosted" and is the factoring reference for `EngineContext`.
10. **Ordered teardown (`CleanupStack` + `ResourceDependencyTracker` + `RegisterExternalCleanup`).** Dependency-ordered, refcounted, tag/type-addressable, open to external systems. Long-session lifecycle management (scene swap, device recreation, mod unload) builds on this rather than fighting it.
11. **The documentation discipline itself.** A maturity-4 vault with commit-traceable sprint docs means the re-plan this review proposes can actually be executed and tracked — most solo projects lack the substrate to absorb a strategy change.

### 5.1 Procedural sim-driven rendering

| Gap | Severity | Status |
|---|---|---|
| SVO incremental update is a façade | 🟥 | confirmed |
| Streaming interface-only; no cache eviction/residency | 🟥 | confirmed |
| No sim-to-render change bridge | 🟥 | partially accurate [corrected] |
| Graph topology frozen after first frame | 🟧 | confirmed |
| No per-frame dynamic-content node | 🟧 | confirmed |
| Upload path buffer-only, unprioritized, single queue | 🟧 | confirmed |
| Synchronous, deadlock-prone cache creation | 🟧 | confirmed |
| Spatial encoding scale ceilings | 🟧 | confirmed |
| Cache identity carries no generator identity | 🟧 | partially accurate [corrected] |

**SVO incremental update is a façade (🟥).** `updateBlock()` (`libraries/SVO/src/SVORebuild.cpp:738-792`) only swaps `EntityBrickView`s and edits `brickGridToBrickView`; it never touches `ChildDescriptors`, so voxels added to a previously-empty region are unreachable by ESVO traversal, and DXT recompression happens only inside full `rebuild()`. The header doc (`LaineKarrasOctree.h:146`) claims the opposite of what the implementation does. The only correct path is `rebuild()` — O(world) per mutation. Prerequisite scale fix: farBit is always 0 and 32-bit indices silently truncate into the 15-bit `childPointer` (`SVORebuild.cpp:435,584`). Direction: complete the documented Phase 3 (dirty-subtree descriptor patching, per-brick recompression, double-buffered swap under `m_renderLock`, byte-range upload deltas), landing far-pointer support with it. Nuance: mutations *within* an already-populated brick are visible to CPU ray casts (live ECS view) — but never to the GPU, whose buffers stay stale until full rebuild + re-cache.

**Streaming is design fiction; nothing evicts (🟥).** `ISVOStreamingManager`/`createStreamingManager` (`SVOStreaming.h:139,323`) have zero implementations and zero includers. CashSystem has no eviction vocabulary (`Erase` exists with zero call sites; `Clear` runs only at device teardown); budget managers track/warn or strict-fail but never reclaim. The built host-side streaming half (`HostBudgetManager`, `BudgetBridge`) has no production consumer. A galaxy-scale world exhausts VRAM and RAM by construction. Direction: implement `createStreamingManager` against the existing `StreamingConfig` contract, backed by a chunk-grained `VoxelChunkCacher` (TypedCacher recipe, keys = generator id + version + params + chunk coord), eviction via string-keyed budgets + `DeferredDestructionQueue`, priority/prefetch from camera events on the bus.

**No sim-to-render change bridge (🟥, [corrected]).** Confirmed: the only production flow is a one-shot bake — `VoxelSceneCacher` constructs its `GaiaVoxelWorld` internally (`VoxelSceneCacher.cpp:474`, private member, no accessor), GPU upload happens once inside `Create()`, and `GaiaVoxelWorld` emits zero change events. **Correction:** "no on-ramp" was overstated — substantial tested building blocks exist unwired: `updateBlock()/removeBlock()/lockForRendering()` on the octree, the `VoxelInjectionQueue` + `VoxelInjector` async injection pipeline (tested, production-absent), `ChunkMetadata.isDirty` helpers, and GaiaArchetypes' dirty-volume observer system. Undertow needs *integration* (world-ownership inversion, a Morton-keyed dirty journal flushed as bus events at FrameStart, a consuming graph node) plus the genuinely-missing GPU delta-upload leg — wiring existing tested components, not building from zero.

**Graph topology frozen after first frame (🟧).** Documented contract (`RenderGraph.h:97`); enforcement is indirect (mutation resets `isCompiled`, `RenderFrame` throws). `RecompileDirtyNodes` is node-local — never re-sorts topology. `RemoveNode` erases by index with no generation check. A session where the sim unlocks new renderable feature classes cannot grow the graph; everything must be pre-wired and toggled. Major rather than blocker only because [[Sprint8-Timeline-System]] already specifies the fix and pre-provisioned passes are a viable short-term workaround. Direction: execute Sprint 8, prioritizing delta commands + generational handles over editor-UI phases.

**No per-frame dynamic-content node (🟧).** All content nodes bake at Compile; `BatchedUpdater` exists precisely for per-frame GPU recording but is dead-ended — `VulkanDevice::RecordUpdates` has zero callers, `BufferWriteRequest` exists only in a doc comment. The gap is *understated* in the original claim: in production nothing drains `BatchedUpdater` at all. Direction: `StreamingBufferNode` (TypedNode recipe) with double-buffered GPU buffers, bus-subscribed dirty events, `BatchedUpdater` queuing in `ExecuteImpl`, costed via `RegisterPhaseProfile` so `TimelineCapacityTracker` can throttle churn.

**Upload path cannot serve streaming (🟧).** `BatchedUploader::Upload` is `VkBuffer`-only (`BatchedUploader.h:142`); the only image-copy path is the blocking init-time `TextureLoader::UploadOptimal` (fence-waited, `exit(1)` on error). No priorities, cancellation, or bandwidth throttling. `VulkanDevice` creates exactly one queue; documented backpressure is fictional (all reservation paths fail fast; the one real caller throws on `InvalidUploadHandle`). Round 2 re-confirmed the single-queue half end to end: `CreateDevice` requests exactly one graphics-family queue (`VulkanDevice.cpp:35,160`), zero `VK_QUEUE_TRANSFER_BIT` selection exists anywhere in the render path, the uploader and every submitting node share that one `VkQueue` (`DeviceNode.cpp:504-510`), and `vkQueueWaitIdle` calls on it (`AccelerationStructureCacher.cpp:466/652`, `DepthBufferNode.cpp:241`) amplify the contention — but `BatchedUploader` itself is queue-agnostic (accepts any `VkQueue` + family index, owns its own pool + timeline semaphore), so only device-layer queue creation/wiring needs changing. Direction: `ImageUploadRequest` on the `UpdateRequestBase` pattern; dedicated transfer queue gated by a new CapabilityGraph node ("DedicatedTransferQueue", queried by string like RTXSupport) with graphics-queue fallback; budget-integrated upload batches.

**Synchronous, deadlock-prone cache creation (🟧).** `TypedCacher::GetOrCreate` runs `Create()` on the calling thread, and both the fast and slow concurrent-duplicate paths block in `.get()` **while holding the cacher lock**, while the creator needs that lock to fulfill the promise — guaranteed mutual deadlock for two threads on the same key, currently latent only because all callers are single-threaded. Direction: drop-lock-before-wait correctness fix first (independent of features), then `GetOrCreateAsync` on a worker pool publishing completion through `WorkerThreadBridge` (built for exactly this, currently unused in production).

**Spatial encoding scale ceilings (🟧).** Verified hard caps: Morton ±2²⁰/axis with **no range validation** (out-of-range coords silently alias); 15-bit childPointer with no overflow guard (corruption past 32,767 descriptors — the first wall hit, well below strategic-map scale); single root `OctreeBlock` (the `blocks` vector is never populated); 1024 bricks/axis grid keys; one entity per Morton cell with silent overwrite that leaks the displaced entity. Direction: chunked multi-volume worlds (decision #5) rather than widening one global octree; implement farBit handling regardless.

**Cache identity carries no generator identity (🟧, [corrected]).** Confirmed and *worse* than claimed: any custom generator name collapses to `SceneType::Custom=255` before keying, and `GenerateScene` then silently falls back to the cornell generator — distinct custom generators alias to one key *and* cannot even be invoked. Unclean shutdown wipes `cache/devices` wholesale (device-scoped only; `cache/global` survives). **Correction:** "nothing external can selectively invalidate" is too absolute — public `Erase(key)` exists and voxel keys are computable via public `ComputeHash()`, but it is vestigial: zero call sites, no enumeration to discover keys, and erasing a scene entry would leak its GPU buffers (per-entry resource cleanup is unwired). Adjacent lifecycle hygiene (unverified minors, recorded for completeness): `DeviceIdentifier` XORs `driverVersion` into the device hash, so every driver update orphans the previous `cache/devices/<id>` directory, and nothing garbage-collects stale directories or evicts in-memory entries — unbounded growth on disk and in memory over a long-lived install; and `Insert()` silently swallows `bad_any_cast` at the type-erased boundary. Direction: hash generator name + version into `ComputeKey`; per-entry magic/version/checksum so session-lock recovery validates per file; move cache-root/session-lock policy from `RenderGraph.cpp` into a host-configurable MainCacher facade.

Minor (unverified, recorded for completeness): single coarse `m_renderLock` stalls frames during rebuilds (fold double-buffering into the Phase 3 work); dual attribute systems unreconciled (runtime `AttributeRegistry` deprecated in the live path — fine for v1's fixed component set, major for the mod ecosystem later); fixed-timestep loop gating dead in the `RenderFrame()` path (the registered 60 Hz PhysicsLoop never ticks — small fix, prerequisite for trusting `LoopBridgeNode` as the sim-tick gate).

**No many-entity draw path (🟥).** `GeometryRenderNode::RecordDrawCall` issues exactly one `vkCmdDrawIndexed`/`vkCmdDraw` — the only two `vkCmdDraw*` call sites in the entire library tree — with counts read once at Compile from static parameters. Zero `VK_VERTEX_INPUT_RATE_INSTANCE` anywhere (all bindings hardcode per-vertex rate); no `vkCmdDrawIndirect` (the `MultiDrawIndirect` flag in `BasicDataTypes.h:33` is an unused enum); no draw list, batching, or culling stage (`InstanceGroup.h` is about parallelizing *node* execution, and is unimplemented anyway). Nuance: fixed-count instancing (INSTANCE_COUNT>1 + SSBO + `gl_InstanceIndex`) is theoretically expressible with a custom shader, but the count freezes at compile and no per-instance attributes exist — the dynamic-thousands-of-units requirement has no path. Direction: `InstancedRenderNode`/`DrawListNode` family via the node recipe; instance SSBO fed by the per-frame update path; indirect draws gated by CapabilityGraph; accumulation rule (finished) for batch fan-in.

**No multi-view / multi-camera (🟥).** `CameraNodeConfig` hard-requires `SWAPCHAIN_PUBLIC` and `INPUT_STATE`; aspect ratio computed from swapchain extent in both Setup and Execute; one topological sort, one execution order, no per-view subgraph concept. A second CameraNode instance is *legal* (the NodeType/Instance split allows it) but would share the swapchain's aspect and the player's input — and has no offscreen target to render into. Direction: model a view as (camera + render target + subgraph); replace the swapchain slot with an extent input from the render-target abstraction; make INPUT_STATE nullable with a host-fed `CameraData` alternative; stamp out per-view subgraphs with a helper mirroring `BenchmarkGraphFactory`'s node-bundle pattern. No core scheduler rewrite needed — execution remains one sorted DAG.

**No offscreen render targets (🟥, [corrected]).** Confirmed at the node layer: every recording node and `FramebufferNode` non-nullably requires `SwapChainPublicVariables*`; compute/RT write `swapchainInfo->colorBuffers[imageIndex].image` directly; the graph-level generic image allocation path is dead (`AllocateResources` placeholder, `FindMemoryType` TODO returning 0). **Corrections:** (1) the gap is confined to the node layer — VMA/Direct allocators create arbitrary images, `DescriptorSetNode::HandleStorageImage` binds arbitrary `VkImageView`s, and `DepthBufferNode` already proves the non-swapchain attachment pattern for depth; the fix is a *producer node* (the research docs already sketch "RenderTargetNode" — [[Competitive-Analysis-Open-Source-2026]]), not new infrastructure. (2) Picking IDs and fog-of-war masks are partially workaroundable today via compute-written storage buffers/images. Round 2 (portrait/embedded-viewport angle) re-confirmed and broadened the finding: the compute path is swapchain-bound too (`ComputeDispatchNodeConfig` requires SWAPCHAIN_INFO/IMAGE_INDEX; swapchain images carry STORAGE_BIT), `FramebufferNode.cpp:148` is the only `vkCreateFramebuffer` in the entire repo, and the sole graph call site of `Resource::AllocateImage` is commented out (`RenderGraph.cpp:988`) — while static 2D portraits via TextureLoaderNode are the one near-term carve-out — not functional as wired today (the one-function `TextureCacher::LoadTextureFromFile` stub breaks the path, §5.4/Phase 4.1) but a single-function fix away (keeping this 🟧 rather than 🟥 in the dialogue domain). Direction: `RenderTargetNode` emitting a bundle shaped like `SwapChainPublicVariables` (or an `IRenderTarget` interface both satisfy — the swapchain struct already has the implicit conversion operators), allocated via `DeviceBudgetManager`, registered in `RESOURCE_TYPE_REGISTRY`; `CompositeNode` for view fan-in.

**No picking/selection pipeline (🟥 as scoped, [corrected — in practice a wiring gap]).** Confirmed: no ID-buffer pass, no async readback of entity-under-cursor, no rect select, no screen→world unprojection anywhere; `DebugBufferReaderNode` is a fence-stalled debug-JSON exporter. **Corrections:** the supporting stack exists — `GaiaVoxelWorld::queryRegion(min,max)` AABB entity gather is implemented *and used in production* by the SVO rebuild; `ISVOStructure::RayHit` carries the hit entity, populated by the brick DDA; mouse events with absolute coordinates already publish on the bus. CPU click-select (unproject + `castRay` → Entity) and drag-select (unproject rect + `queryRegion`) are buildable today from existing primitives. "Target is impossible" was overstated; GPU pixel-exact picking remains new work (depends on offscreen targets + a ring-buffered readback node). Direction: two-tier — CPU path now, publishing `PickResultEvent` on the bus; GPU ID-buffer + `PickingReadbackNode` (PerFrameResources N-frame-latency pattern) after the render-target abstraction lands. (Round 2 re-confirmed and sharpened from the grand-strategy side: `GaiaVoxelWorld::getEntityByWorldSpace`/O(1) `getEntityByMorton` complete the ray→entity path, `CameraData` already carries invProjection/invView for the unproject, and batch/frustum SVO queries are needed only for drag-box selection — single-click picking is glue over existing APIs; `MouseButtonEvent` is declared but never published by InputNode.)

**No per-frame sim→renderer data path (🟥, [corrected]).** Confirmed end-to-end: content nodes are Compile-only; the world is cacher-internal; `updateBlock` doesn't reach the GPU. **Corrections:** two per-frame host→GPU channels do exist — (a) push constants: camera/time repack and re-record every frame through the gatherer → dispatch chain ("nothing animates" was false; the camera animates; *scene content* cannot); (b) `AccelerationStructureNode` in Dynamic mode streams TLAS instance transforms per frame into persistently-mapped ring buffers (`DynamicTLAS`/`TLASInstanceBuffer`/`TLASInstanceManager::UpdateTransform`) — RT-specific, currently seeded with one hardcoded identity instance and not driven by any external API, but the plumbing pattern is built and tested. Direction: `DynamicBufferNode` generalizing the TLAS-instance-buffer + `PerFrameResources` patterns, with dirty flags so unchanged frames cost nothing.

**No terrain path (🟧).** The only world content is the four canned procedural scenes (cornell/noise/tunnels/cityscape); the `HeightmapSampler` exists only as fully commented-out code (the IMPLEMENTATION_STATUS doc claiming it "Complete" is stale); no splatting, no overlay channels; voxel-as-terrain hits the §5.1 scale ceilings and unimplemented streaming. Direction: decide voxel vs heightmap early (decision #5); either way, chunk terrain through the TypedCacher recipe and the streaming upload path.

**No fog-of-war (🟧, [corrected]).** Confirmed: zero FoW capability — no visibility mask, no compute updater, no consumption hooks, no explored-vs-visible state. **Corrections to the variant sub-claim:** the C++ `#if` is *not* the only variant mechanism — `ShaderBundleBuilder::SetStageDefines` is a fully built per-stage preprocessor-define variant system (hashed into the cache key) with zero callers; and spec constants are reachable for compute pipelines via CashSystem's `ComputePipelineCreateParams::specMapEntries` (wired to `VkSpecializationInfo`), though `ComputePipelineNode` never populates them and reflection of spec constants is a stub. FoW on/off per pass is achievable today with defines; the missing piece is plumbing through node configs, not mechanism. Direction: `FogOfWarNode` (compute pattern) writing R8/R16 visibility to an offscreen target with ping-pong explored accumulation; close the spec-constant plumbing for cheap runtime permutations.

**Per-node hand-routed sync; effectively one submitting pass per frame (🟧, partially accurate [corrected] — round 2).** Confirmed: every dispatch/draw/traceRays node takes IMAGE_INDEX, CURRENT_FRAME_INDEX, IN_FLIGHT_FENCE, and both semaphore arrays as explicit slots (15–17 inputs on dispatch/draw configs; 14 on TraceRays), hand-wired per pass in both graph factories with no auto-routing rule. Worse than originally claimed: each leaf node independently `vkQueueSubmit`s waiting the frame's single `imageAvailable` binary semaphore and signaling `renderComplete` (`ComputeDispatchNode.cpp:236-254`, `GeometryRenderNode.cpp:247`, `TraceRaysNode.cpp:355`) — so only **one** submitting node per frame is valid, and dozens of RTS passes cannot compose at all with these nodes; [[Sprint8-Timeline-System]] itself names the fix (TimelineNode submission coordinator). **Corrections:** execution is not architecturally single-threaded — a TBB parallel task executor is fully integrated into `RenderFrame()` (dependency-driven waves), just default-off, unused by applications, and CPU-side only — with no multithreaded command-buffer *recording* contract (it requires per-node thread-safety guarantees nothing enforces, the experimental status the audit flagged); and the graph is not structurally one-frame-in-flight — `FrameSyncNode` implements a 4-deep frames-in-flight ring (MAX_FRAMES_IN_FLIGHT=4); the single-frame behavior comes from `PresentNode`'s `WAIT_FOR_IDLE` parameter (`vkDeviceWaitIdle` every frame), which both applications explicitly set true "for compatibility". `MultiDispatchNode` (6 inputs, no sync slots, auto-barriers, group accumulation) already batches N compute passes — but records-only and test-only. Direction: promote sync to the graph compile phase (SlotRole metadata already encodes per-frame dependencies; the 5-phase Compile pipeline anticipates this analysis), keep FrameSyncNode as the per-flight primitive, make recording nodes' sync slots optional/auto-wired, retire the WAIT_FOR_IDLE default, and add per-frame conditional execution so minimap/FoW passes can run at reduced rates.

Minor (unverified, recorded for completeness): no decal/overlay node (pure absence; trivial once instancing + offscreen targets exist). The camera gap was promoted to a full round-2 entry in §5.3 (orbit-mode-only, perspective-only, swapchain-bound — "free-fly" in the original claim was itself wrong: `UpdateCameraData()` is explicitly ORBIT MODE).

- **No representation-switching machinery — "LOD of meaning" (🟧, partially accurate [corrected] — round 2).** Confirmed: nothing selects a different representation per zoom band — no impostor/icon/aggregate node exists (full 32-node roster checked; "impostor" appears only in docs), and the live `RenderFrame()` path executes every compiled node every frame unconditionally. Direction: phase 1 needs no graph mutation — an `enabled` execution predicate honored in `RenderFrame()`'s per-node loop, settable via the existing string-keyed `SetParameter`, plus a hysteresis `ZoomBandChanged` bus event (mirroring SwapChainNode's WindowResized → MarkNeedsRecompile pattern); phase 2 aligns with Sprint 8's StateMachineNode + GraphEditorNode frame-boundary deltas for true subgraph splicing. Zoom-band thresholds become node parameters, data-drivable immediately.
- **Single fixed-purpose camera unsuited to multi-scale strategic maps (🟧, confirmed — round 2).** `CameraNode` is one perspective orbit camera explicitly sized for the research scene: `zoomSpeed = 100.0f; // Scaled for 128^3 world`, orbit distance clamped to [5,120] (`CameraNode.cpp:271-273`), `glm::perspective` only (lines 88/167; zero `glm::ortho` in code), hard-bound to the swapchain (SWAPCHAIN_PUBLIC required; aspect computed from swapchain extent in both Compile and Execute), FOV/near/far as source literals in the application layer (`VulkanGraphApplication.cpp:770-772` — runtime-settable parameters whose values are hardcoded literals). No zoom-to-cursor: zoom is keyboard W/S, and `MouseScrollEvent` exists with no consumer anywhere — not even wheel zoom. No camera-relative/floating-origin convention (zero repo hits) while Core's Morton encoding caps coordinates at ±2²⁰/axis — nothing scales to a galaxy map. Simultaneous map + minimap + portrait cameras have no representation: a second CameraNode instance is legal, but there is no viewport routing or compositing path, and both instances would read the same full-swapchain extent and the same single InputState. Direction: projection-mode string parameter via magic_enum (the GraphicsPipelineNode cullMode pattern), zoom-curve/bounds parameters, extent input from the render-target bundle (the only blocker to multiple instances), and a camera-relative transform convention in `CameraData` — which already flows through FieldExtractionModifier into push constants, so the data path needs no new machinery.
- **Map-mode overlays blocked by frozen topology and absent pass toggling (🟧, partially accurate [corrected] — round 2).** Map modes (political/economic/trade-lane/FoW views) need instant pass enable/disable/reparameterize. Confirmed: instant graph-level pass toggling genuinely does not exist; `SetParameter` → `MarkNeedsRecompile` → `RecompileDirtyNodes` is the only proven runtime mutation path; and one aspect is *worse* than claimed — rewiring an occupied input slot is process-fatal `std::exit(1)` (`RenderGraph.cpp:224`). **Corrections:** the first-frame freeze is contract-only with disconnect primitives existing unwired (~70%, as §5.5); a per-frame gate (`ShouldExecuteThisFrame`) is partially built but never checked by the production `RenderFrame()`; and "only lever is SetParameter + recompile" is overstated — push constants repack and re-record every frame *without* recompile (`ComputeDispatchNode.cpp:215-232`), so map modes are approximable **today** via ubershader branching on an overlay-mode integer routed through the existing ConstantNode → FieldExtraction → push-constant path, with `SetStageDefines` variants and compute spec-constant plumbing (both built, both caller-less) for cheap permanent permutations. The gap is missing orchestration over existing primitives, not wholesale capability absence. Direction: shader-driven map modes short term; the execution predicate above for whole-pass toggling; Sprint 8's GraphEditorNode/ValidationNode/SnapshotNode splice machinery for mod-added overlay passes.
- **No data-driven presentation definitions (🟧, partially accurate [corrected] — round 2).** The presentation-side instance of §5.5's data-driven gap: no graph serialization (GraphSerializer is Sprint 8 Phase 5 planning only — zero code hits), no material/overlay/map-mode/icon-set definition format anywhere, and the main app's pass topology, shader variant selection (`#if USE_COMPRESSED_SHADER`), and camera parameters are compile-time C++. **Corrections:** two on-ramps exist in embryo — the benchmark harness runtime-parses JSON selecting pipeline type, shader files by name, scenes, and procedural parameters (`BenchmarkConfigLoader::LoadFromFile` feeding `ShaderLibraryNode` builders), proving the node-config architecture is data-drivable; and shaders are already runtime-compiled GLSL files on disk — moddable data, not compiled C++. Both are confined to the benchmark/shader paths and reach no game-presentation concept, so the conclusion stands at reduced severity: the on-ramp is partial and unexposed, not absent. Direction: start narrow — a JSON "presentation manifest" (icon atlas paths, overlay shader files, zoom-band thresholds, color ramps, label styles) consumed at startup and on a ReloadManifest event; every ingredient (nlohmann config pattern, runtime shader compile, TypedCacher, string-keyed SetParameter) exists, and the manifest schema seeds the eventual GraphSerializer mod vocabulary.

Minor (unverified, recorded for completeness): benchmark presentation policy (IMMEDIATE-first, no vsync API, no `oldSwapchain`/OUT_OF_DATE recovery — rides the proven SetParameter→recompile path); input vocabulary too thin (no action mapping, contexts, priority/consume ordering on the bus, no gamepad).

- **No text or font rendering subsystem (🟥, confirmed).** The single largest absence in this domain — see §5.3. Direction: `GlyphAtlasCacher` (TypedCacher recipe, stb_truetype/FreeType PRIVATE dep) + `TextGeometryNode` quad streams + runtime-compiled SDF shader via the existing `RegisterShaderBuilder` seam.

- **UI-over-3D compositing (🟥, partially accurate [corrected — claim narrowed, severity stands]).** The verified core: **alpha blending is genuinely inexpressible** — `blendEnable` hardcoded `VK_FALSE` in both `vkCreateGraphicsPipelines` paths, no blend parameter anywhere. **Corrections:** the other two claimed reasons are wrong — `RenderPassNode` already exposes `color_load_op="Load"` (clear values are ignored under LOAD, so a UI pass preserves compute output), and the compute→raster layout chain already works (`TransitionImageToPresent` GENERAL→PRESENT_SRC after dispatch + `initial_layout="PresentSrc"` on the render pass; `MultiDispatchNode::QueueBarrier` accepts arbitrary `VkImageMemoryBarrier2`). A load-preserving raster pass over the ray-march output **is wireable today**; binary-transparency UI via fragment discard would work now. Only true alpha blending is blocked, by one hardcoded struct — and that suffices to keep the blocker: per the verification record the headline stands ("alpha blending is genuinely inexpressible"), so the two refuted supporting reasons narrow the *claim*, not the *severity*, which holds 🟥 until the BLEND_MODE parameter lands (Phase 2). Residual caveats: `ImageLayout` param enum lacks General; the render pass's external subpass dependency is not compute-aware; no existing wiring sets `color_load_op`. Direction: BLEND_MODE string parameter (the CULL_MODE pattern), honor the existing load-op, small `ImageBarrierNode`.
- **No offscreen targets for portrait scenes / embedded viewports (🟥 at §5.2; re-confirmed round 2 from this domain at 🟧).** The same render-target gap as §5.2 viewed from dialogue: a 3D character rendered into a dialogue panel, pre-rendered UI panels, and minimap content cannot be rendered to texture. Major rather than blocker here only because static 2D portraits are a small, scoped fix away rather than new infrastructure: implement the one-function `TextureCacher::LoadTextureFromFile` stub (Phase 4.1) or wire the dormant `TextureLoader::UploadOptimal` path — not functional today as wired (see the runtime-image entry above). Round 2's strengthened evidence (compute path also swapchain-bound; only one `vkCreateFramebuffer` in the repo) is folded into the §5.2 entry; direction (RenderTargetNode modeled on DepthBufferNode + optional image-view/format/extent slots on Framebuffer/RenderPass nodes) is scheduled in Phase 2.
- **Input routing unsuitable for UI: no text input, no consume/priority semantics, polled Win32 state (🟧, confirmed — round 2).** `InputNode` polls `GetAsyncKeyState`/`GetCursorPos` per frame (`InputNode.cpp:159-176,235-239`) against a hand-picked KeyCode subset (WASD/QE/C, modifiers, arrows, digits — the enum lacks most of the alphabet and all punctuation), and `WindowNode`'s WndProc handles only lifecycle messages — no WM_CHAR anywhere in the repo, so text fields and IME for dialogue input are impossible. Aggravating: `MessageBus.h:19-22` *documents* "Returns true if handled… control whether the event continues propagating", but `MessageBus.cpp:242-245` only logs the handler's bool and dispatches to all subscribers unconditionally — documented consume semantics the implementation never enforces (the plain typed `Subscribe` wrapper even hardcodes `return true`). Subscriptions carry no priority field, no focus/capture concept exists, and no UI layer exists to arbitrate — a UI panel cannot reliably claim a click before camera/world-picking sees it. Direction: route input through the window layer's event callbacks (WM_CHAR/WM_KEYDOWN/WM_MOUSEWHEEL on this branch; GLFW char/scroll callbacks on `main`'s merged port — §5.6) publishing a `TextInputEvent` via AUTO_MESSAGE_TYPE; priority field + honored stop-propagation in the dispatch loop (mechanical, default-priority-preserving); an `InputRouterNode` upstream of CameraNode owning focus/capture and demuxing InputState into UI vs world contexts.
- **No runtime image upload or name-addressable texture registry (🟧, partially accurate [corrected] — round 2).** Confirmed: `BatchedUploader` is genuinely VkBuffer-only; no async/batched/streaming image upload is integrated with ResourceManagement; no partial-image (atlas region) update path. **Corrections:** (1) a `vkCmdCopyBufferToImage` path *does* exist — `TextureLoader::UploadOptimal` (`TextureLoader.cpp:238`) is a complete staging→VkImage upload with mip loops, layout transitions, views, and samplers — but synchronous (per-texture fence wait), file-path-only, and dormant (no callers outside its own library); (2) a string-keyed lookup *does* exist — `TextureCacher::GetOrCreateTexture(filePath, …)` — but is path-keyed rather than logical-name-keyed, and **worse than claimed**: its `LoadTextureFromFile` is a TODO stub returning a 1×1 fallback with `image == VK_NULL_HANDLE`, which `TextureLoaderNode.cpp:172` then throws on — the only graph-wired texture path cannot produce a real texture; (3) "no runtime swap" is architecturally overstated — `SetParameter(FILE_PATH)` + `MarkNeedsRecompile` would reload via the proven blocking node recompile. An integration gap, not a total absence. Direction: image-upload request kind on `BatchedUploader` (reusing StagingBufferPool + timeline tracking via the polymorphic `UpdateRequestBase::Record` pattern); implement the TextureCacher stub and layer a string-keyed runtime texture registry over it; `DynamicTextureNode` triggering the existing dirty-recompile so dependent descriptor sets refresh.
- **No immediate-mode UI integration point (🟧, partially accurate [corrected] — round 2).** Confirmed: no ImGui (or any UI library) exists in code or `dependencies/CMakeLists.txt` (docs mentions only), and no node exposes a record-into-active-render-pass callback — the only `vkCmdBeginRenderPass` caller is `GeometryRenderNode` with a fixed Begin/Bind/Draw/End sequence. **Corrections:** the "blocked by missing primitives" framing is overstated — three of the four cited primitives substantially exist: per-frame persistently-mapped HOST_VISIBLE buffers (`PerFrameResources`), batched staging uploads to arbitrary `VkBuffer`s (`VulkanDevice::Upload`), key/mouse event publication via InputNode, and the CPU-pixel→GPU staging machinery (`UploadOptimal` consumes raw `PixelData`; only the public entry is file-path-bound). Genuinely missing: a blend-enabled pipeline (`blendEnable=VK_FALSE` hardcoded, no blend factors anywhere), a per-frame rewritable vertex/index node, wheel/text-input publishing, and a public from-memory texture entry. The integration route is open today: an `ImGuiNodeType` registered from host code via `NodeTypeRegistry::Register<T>` (the proven external-registration seam), wrapping ImGui's own Vulkan backend, taking the same slot set as GeometryRenderNode. Direction: build it as the forcing function — it makes the blend parameter, LoadOp::Load pass begin, compute→raster barrier, and text input land in engine seams rather than ad hoc hacks (scheduled Phase 4).
- **UI layer has no data-driven or mod-facing surface (🟧, partially accurate [corrected] — round 2).** Even with rendering solved, mods cannot declare UI: no stable string identity for fonts/textures/panels (cache keys are content-derived hashes, not names), no graph-from-data path, and no mod-reserved EventCategory range — UI/dialogue event domains (DialogueAdvanced, WidgetClicked) cannot be *named* without engine edits. **Corrections (cross-referencing Appendix B):** graph wiring is not exclusively compile-time — runtime string `AddNode(typeName, instanceName)`, index-based `ConnectNodes`, `GetInstanceByName` + `SetParameter` all exist; the event system is *type-open* even though the category enum is closed (`MessageType` is user-extensible by design via AUTO_MESSAGE_TYPE, and dispatch validates no enum — a C++ host can add dialogue events today, and unused category bits are castable); `TextureCacher` keys do include the file path (identity content-derived, not stable). Data-only mods, however, have no surface at all. Direction: make UI pass nodes the *first* GraphSerializer serialization targets (small, regular, high-value proving ground); string-named UI assets via the cacher name→factory seam; reserved host/mod EventCategory bits + the runtime event-name registry (§6 Layer 1).

- **Process-fatal error model (🟥, confirmed).** All five cited failure modes verified at exact locations: `std::exit(1)` at `RenderGraph.cpp:224`; `exit(-1)` in `VulkanSwapChain.cpp:249`; `CreateDevice` throwing despite its declared `VulkanStatus` return; `ConnectionBatch::RegisterAll` throwing on first failure; `RenderFrame()` returning only `VK_SUCCESS` (making the host's existing error check dead code — `NodeInstance::Execute` returns void so node failures cannot propagate). Plus ~20 more `exit(1)` calls in the texture loaders. Mitigations exist in embryo (`std::expected` `VulkanResult`/`VulkanStatus`, `ConnectionResult`) but every externally-triggerable entry converts failure into exit/throw. Round 2 corrections (boundary-domain re-verification): the failure model is *mixed*, not uniformly fatal — sequential-mode node failures and graph-construction errors (invalid handles, bad slot indices) throw catchable `std::runtime_error` that reaches the host; OUT_OF_DATE/SUBOPTIMAL swapchains recover internally via event-driven recompilation; the parallel executor exposes `HasErrors()/GetErrors()` (though `RenderFrame` ignores them); and the zero-extent `exit(-1)` is **not** reachable by minimizing the window — minimization is filtered/paused at three layers (WndProc SIZE_MINIMIZED filter, renderPaused, deferred recompile), making it a startup edge case (Appendix B). The unrecoverable residue: three specific exits (duplicate connection, zero surface extent at creation, the 20 texture-loader `exit(1)`s), the always-VK_SUCCESS return channel, and silently ignored parallel-task failures. Direction: mechanical generalization of the existing result types; fatal-class failures published as bus events.

Direct slot-to-slot wiring is already data-drivable with existing APIs; the genuinely hard residue is variadic/SDI shader-binding connections, accumulation ordering, and field extraction (compile-time member pointers), which need real engineering. Direction: Sprint 8 GraphSerializer scoped as the *public* format; auto-generate runtime slot schemas from the macro configs (the SDI trick applied to nodes); `Connect(nodeName, slotName, ...)` facade over the existing pipeline.
- **Graph frozen / no disconnect (🟥, partially accurate [corrected]).** Same underlying freeze as §5.1's 🟧 entry — two distinct domain claims, two severities: a blocker here because a mod-injected pass has no workaround, a major there because Sprint 8 plus pre-provisioned passes mitigate sim-driven growth. As §5.1, plus corrections: disconnect *primitives* exist unwired (`GraphTopology::RemoveEdge`/`RemoveNode`, `NodeInstance::RemoveDependency` — unit-tested, zero production callers, no combined inverse of what ConnectNodes does); `GraphLifecycleHooks::ClearAll/ClearGraphHooks/ClearNodeHooks` exist (never called; per-hook unregistration impossible); `RecompileDirtyNodes` + `CleanupStack::ResetExecuted` are designed for post-cleanup revival. ~70% of the building blocks exist and need orchestration. One finding is *worse* than claimed: `CleanupByTag` leaves nodes in the execution order and the execute loop checks `NodeState`, not the cleanedUp flag — destroyed-resource nodes keep executing.
- **No instantiable engine facade (🟥, confirmed)** and **no consumable build artifact (🟥, confirmed).** Detailed under §5.6.
- **No mod content pipeline: SDI headers are the consumption path, no VFS, no namespaced identity (🟧, confirmed — round 2).** Runtime GLSL compile + reflection fully works (§4, strength 5), but the engine *consumes* shaders through compile-time-generated SDI headers `#include`d by application C++ (`VulkanGraphApplication.cpp:43` includes `VoxelRayMarch_CompressedNames.h`; constexpr BINDINGs wired at lines 1127-1187; variant chosen by `#if USE_COMPRESSED_SHADER`) — any shader-interface change recompiles the host, the exact opposite of mod-shipped shaders. `ShaderPreprocessor::ResolveIncludePath` resolves includes solely from the real filesystem (no VFS/includer seam; glslang has no custom includer); shader identity is unnamespaced 64-bit FNV (`ComputeSHA256Hex` is misnamed FNV); hot-reload machinery is complete-looking but disconnected end to end (`ShaderHotReloadReadyMessage` has zero publishers; `ShaderManagement::ShaderLibrary` has no consumers — the app uses the builder-wrapping ShaderLibraryNode; no file watcher in the loop); and spec constants are unreachable from the builder API *and not even reflected* (`SpirvReflector.cpp:736-743` is an empty stub — larger than claimed). Nuance in the engine's favor: descriptor layouts are built at runtime from reflection and literal bindings are accepted, so SDI is a convenience over reflection, not a hard runtime dependency — but all wiring is compiled host C++ regardless. Direction (§6 Layer 2): promote the reflection path to first-class and demote SDI to an internal optimization; include-resolver/VFS seam on the preprocessor; mod/package namespace prefix on shader UUIDs; close the hot-reload loop once end-to-end (file change → AsyncShaderBundleBuilder → HotReloadReady → MarkNeedsRecompile — every stage exists, only the wiring is missing).
- **EventBus: observable, not operable — no stable identity, no command semantics, no scoping (🟧, partially accurate [corrected] — round 2).** Confirms and sharpens §3.10. Identity is *worse* than claimed: `AUTO_MESSAGE_TYPE()` = base + `__COUNTER__` is per-translation-unit and the macro is used across three separately-includable headers, so IDs can diverge across TUs **within one build** depending on include order — and `RenderPauseEvent` is defined twice (EventBus:: and EventTypes:: namespaces) with different auto IDs. Closed EventCategory enum, `void*` device handles (2 of ~27 event types, both core device events), and one global bus mixing engine internals with app events all confirmed. **Corrections:** (1) reacting-by-publishing does **not** deadlock — `Publish()` takes only the queue/stats mutexes; the re-entrancy hazard is real only for `PublishImmediate()`/`Subscribe()`/`Unsubscribe()` called inside a handler; (2) request/response is not entirely absent — ad hoc pairs exist (CleanupRequested/Completed with requestId, DeviceSyncRequested/Completed driving `vkDeviceWaitIdle` via the bus, WorkerThreadBridge workID correlation, WindowClose→ShutdownAck) — what's missing is a *first-class* command API with reply routing to the requester and a validation/rejection channel; (3) `SubscribeCategory`'s 64-bit per-bit filtering is a weak scoping mechanism; absent is isolation/namespacing and category registration. Direction unchanged (§6 Layer 1): runtime event-name registry, command envelope with correlation IDs, snapshot-before-dispatch re-entrancy fix, reserved host/mod category bits.
- **No script-binding-ready boundary (🟧, partially accurate [corrected] — round 2).** Every enumerated leak verified: raw Vulkan handles and `VulkanDevice*` as slot currency across 50+ public headers, `gaia::ecs::Entity` in voxel APIs, `std::any` in 15 public headers, glm in 25+, typeid-keyed registries, `AllocationHandle = void*`, vtable-bearing event structs, zero `extern "C"`/export macros — and all 15 libraries are STATIC, so the typeid/DLL fragility is a forward-looking concern for the mod scenario, not current breakage. **Correction:** "a shim has nothing to bind to" overstates — an *embedded* (same-build, statically linked) script shim could target existing string-keyed, value-typed seams today: `NodeParameterManager::SetParameter` over the ParamTypeValue variant, NodeTypeRegistry string lookup, POD uint32 NodeHandle, integer event IDs + category bitmasks (not RTTI), and runtime GLSL-string compilation. These are bindable *seams*, not a boundary — none header-isolated or ABI-stable, and `__COUNTER__` event IDs rule out cross-boundary event identity entirely. Direction unchanged (§6 Layers 0/3): one thin facade where only opaque generational u64 handles, strings, and ParamTypeValue cross; templates/SDI/typed slots stay the internal fast path.
- **Connection subsystem closed to consumers (🟧, partially accurate [corrected] — round 2).** Confirmed: `ConnectionBatch`'s only constructor hardcodes `ConnectionRuleRegistry::CreateDefault()` (`TypedConnection.h:158-160`; `registry_` private, no setter or alternate constructor), so `RegisterRule` — open in principle — cannot reach the supported wiring path; `debugTag` is write-only and `RegisterAll` destroys the pending contexts + modifiers. **Corrections:** "no introspection, no record" is overstated — resolved direct *and* variadic connections persist `GraphEdge` endpoints in `GraphTopology` (`RenderGraph.cpp:256-263`, `VariadicConnectionRule.cpp:151-158`), enumerable via public `GetTopology()` → `GetEdges()/GetIncomingEdges()/GetOutgoingEdges()` with `RemoveEdge()` available for a disconnect to consult; `GetRules()/RuleCount()` exist explicitly for introspection; and `UnifiedConnect::ValidateConnection` is a standalone, tooling-usable validation entry. Residual gaps: `GraphEdge` carries zero metadata (rule, modifiers, debugTag, sortKey all discarded); accumulation connections add only a node-level dependency — invisible to edge enumeration; and no high-level disconnect reverses resource wiring + dependency + edge together. Direction: registry-injection constructor on ConnectionBatch; a `ConnectionRecord` appended at `ConnectionPipeline::Resolve` (all the data is present in `ConnectionContext` at that moment); facade enumeration — unblocking introspection, disconnect, serialization, and editor tooling at once.
- **Resource/cache identity unpublishable — mods cannot name, query, pin, or invalidate entries (🟧, partially accurate [corrected] — round 2).** Confirmed at the entry level: identity is a uint64 from `ComputeKey(CreateInfo)`, *protected* in TypedCacher and all 13 cachers, so external code cannot even compute a key for Has/Get/Erase; no pin/retain or entry enumeration anywhere; MainCacher is a Meyers singleton; the relative `"cache"` root is hardcoded in five sites (§3.5). **Corrections:** the type universe is *not* sealed at the cache layer — `RegisterCacher` is a public runtime registration API with name-based factories (`CreateCacherByName`); the RESOURCE_TYPE_REGISTRY static_asserts seal RenderGraph's typed-connection types, not cache types (with `UnknownTypeRegistry` as a runtime escape hatch even there); *domain-level* naming and enumeration exist (every cacher is a string-named domain; `GetRegisteredTypes/GetActiveDevices/GetStats`); invalidation partially exists (`Erase/Clear`, `ClearDeviceCaches`, DeviceInvalidationEvent auto-clear); observability is logging-only in CashSystem, but the parallel `ShaderCacheManager` already has everything this claim says is missing for its domain (string keys, Lookup/Contains/Remove, configurable directory, hit/miss stats with GetHitRate, LRU eviction) — a working in-repo template. Persistence policy is *split* (lazy load in MainCacher; save/session-lock orchestration in RenderGraph), not wholly misplaced. Direction unchanged (§6 Layer 2): generalize the two proven seams — name→factory instantiation into named cache domains with string/GUID keys, and the DeviceInvalidationEvent channel into a public invalidation/observability surface; cache-root/session-lock policy into a host-owned MainCacher config; per-mod namespacing falls out of domain names (`modid:texture:ui/icon_fleet`).
- **Documented anti-moddability positioning vs roadmap allocation (🟧, partially accurate [corrected] — round 2).** Confirmed: `Sprint8-Timeline-System.md:178` reads verbatim "Self-contained applications (not plugin hosts)" with "Large ecosystem of compatible tools" listed as a deliberate sacrifice; zero embedding/consumer documentation; no API stability/semver/deprecation *policy*; no roadmap line item for moddability or embedding; 30 GPL-3.0-marked Sprint-6 files. **Corrections:** (1) the hours were overstated — Sprints 7 + 11–14 sum to 614h, not ~1,100h (Multi-GPU is Sprint 10 at 106h; Sprints 12/13 are GPU Procedural Generation and Skin-Width SVO, not the four topics originally listed; the full Sprint 7–14 table sums to 936h); (2) the GPL headers are an internal inconsistency, not the project license — root LICENSE is MIT and the GPL-marked files themselves reference it; (3) the roadmap is not 100% moddability-adverse — Sprint 8's 144h builds ~80% of the mod-API mutation machinery, just not framed as a moddability deliverable, softening the "every gap deprioritized by default" inference. Direction: an explicit "VIXEN as a library / engine-ops API" workstream superseding the Framework Positioning paragraph; Sprint 8 specified against public-API requirements (decision #1); license audit before any external consumer integrates (Phase 0); Undertow named consumer zero in an embedding guide.
- Minor (unverified, recorded for completeness): sandboxing/quotas absent (string-keyed strict budgets exist; attribution and bus-published warnings don't — fine until third-party packages load); mod-developer diagnostics not productized (debugTags discarded, no SubscribeAll tracer shipped, no VK_EXT_debug_utils naming, two profiling stacks with no shared sink).

## 6. Moddability & Engine-Ops API Direction

The findings converge on a four-layer boundary, each layer grounded in a seam that already exists. The strategy throughout: **formalize what works internally; do not invent parallel systems.**

### Layer 0 — Core C++ API (the embedding contract)
*Grounded in:* `BenchmarkRunner`'s working bring-up, the app's injected member aggregate, `RegisterExternalCleanup`, `VulkanResult`/`ConnectionResult`.

- `Vixen::EngineContext` owning what `VulkanGraphApplication` news up today (`NodeTypeRegistry`, `MessageBus`, `RenderGraph`(s), `MainCacher*`, `CalibrationStore`), constructed from an `EngineConfig` (JSON-loadable). The host owns the loop and calls `PumpEvents()/Update(dt)/RenderFrame()`.
- **Uniform recoverable errors at every entry point** — the existing `std::expected` types generalized; fatal-class events (device lost, OOM) additionally published on the bus. This is layer-0 because every layer above returns these results to mods as diagnostics.
- **Generational opaque handles** (index + generation) for nodes, connections, resources, cache entries — replacing raw vector indices and `typeid` keys that cannot cross a DLL boundary.
- De-singletonized `MainCacher`/capability state/`ProfilerSystem`; severed CMake layering; installed/exported targets. License hygiene resolved (repo is MIT; stray GPL-3.0 headers on Sprint-6 files must be corrected before any external consumer).

### Layer 1 — Command/event surface (the operations spine)
*Grounded in:* the injected `MessageBus`, `AUTO_MESSAGE_TYPE` openness, `SubscribeAll`, `WorkerThreadBridge`, the WindowClose/ShutdownAck handshake precedent.

- **Runtime event-type registry:** stable string/hash identities mapped to the existing constexpr types at startup, with payload schemas — so events become referenceable from data/scripts and survive recompilation. (`__COUNTER__` IDs stay as the internal fast path.)
- **Command layer distinct from notifications:** invocable operations with arguments, validation, and typed replies — `SetNodeParameter`, `Connect`, `LoadGraph`, `QueryPick`, `SetBudget`. The seed exists: `GetInstanceByName` + `SetParameter` over `ParamTypeValue` is already operation-shaped; the command layer wraps such calls in request/reply envelopes with Layer-0 error results.
- **Dispatch hardening:** deferred subscription mutation (fix the re-entrancy deadlock), subscriber priority + consume semantics (UI claims clicks before world picking — required by two domains), and **bus scoping** so engine-internal traffic (DescriptorInvalid) is firewalled from mod-visible events. Reserve a host/mod `EventCategory` bit range now (one-line enum change). Add a throughput budget alongside: every event today is a heap-allocated `unique_ptr` dispatched through a mutex-guarded map walk with no batching, coalescing, or per-frame budget — a deep sim streaming thousands of entity-changed events per tick would swamp it. Phase 3's Morton-keyed dirty journal mitigates by design (one region event coalesces many voxel mutations); the bus itself still needs pooled payloads and coalesced delivery before mods publish at sim scale.

### Layer 2 — Data-driven definitions (what mods author)
*Grounded in:* Sprint 8's GraphSerializer spec, the macro-regular NodeConfigs, `m_nameToFactory`, `CapabilityGraph`, `BenchmarkSuiteConfig::LoadFromFile`, the runtime shader path.

- **Graph/scene description format** (JSON): node types, instances, parameters, connections by string — Sprint 8's GraphSerializer *scoped as the public format*. The `CONSTEXPR_NODE_CONFIG`/`INPUT_SLOT` macros are regular enough to auto-generate runtime slot schemas per node type (the same trick SDI generation already performs for shader interfaces); `BuildRenderGraph()`'s uniform Connect vocabulary is the mechanical test corpus.
- **Connection records:** persist (src, dst, slots, rule, modifiers, debugTag) at `ConnectionPipeline::Resolve` time — prerequisite for introspection, disconnect, *and* serialization, and currently all the data is in `ConnectionContext` and simply discarded.
- **Capability manifests:** document + version the CapabilityGraph key space; mods declare required/optional capabilities, engine answers at load (the Profiler's `requiredCapabilities` gating is the in-repo precedent).
- **Named cache domains and string/GUID cache identity** (generator id + version + params), enumerable manifests, explicit load/save/evict/pin operations on the MainCacher facade.
- **Shader/material packages:** the runtime `ShaderBundleBuilder` + reflection path promoted to first-class (SDI headers demoted to internal optimization); a virtual filesystem / package mount for mod-shipped GLSL with engine include libraries; mod-namespaced identity replacing bare 64-bit FNV UUIDs.

### Layer 3 — Script-binding readiness
*Grounded in:* `ParamTypeValue` (already a near-POD variant), opaque handles from Layer 0, string addressing from Layers 1–2.

- A thin boundary where **only handles, strings, and the POD variant cross** — no `gaia.h`, glm, STL containers, or `Vk*` in mod-facing signatures. A C shim (and hence Lua/wasm bindings) becomes feasible on top mechanically.
- Not scheduled before the layers below stabilize; the design constraint it imposes (POD-able payloads, no template entry points on the boundary) must be honored from Layer 1 onward so nothing has to be redesigned.

**Sequencing note:** Layers 0–1 are prerequisites for everything in §5.5; Layer 2's graph format is the moddability payoff and doubles as the engine's own scene/zoom-band/view-definition format — build it once, for both consumers. The first shippable mod surface (curated: parameters, shader packages, data graphs) does not require Layer-3 sandboxing; per-mod quotas ride the existing string-keyed strict budgets when third-party packages arrive.

## 8. Risks & Open Questions

### Risks

1. **Roadmap capacity collision.** [[Production-Roadmap-2026]] commits Q2 2026–Q1 2027 (Sprints 7–14, 936h — round 2 corrected the earlier ~1,100h figure) to voxel physics, timeline, auto-sync, multi-GPU, soft body, procedural generation, VR. This review's Phases 1–4 occupy the same calendar. This is a strategy decision, not a scheduling tweak — partial adoption (e.g., Sprint 8 done right + Phase 2) still pays off even if the physics workstream continues, but pretending both fit is the failure mode.
2. **Sprint 8 implemented against the wrong requirements.** The highest-leverage, lowest-cost intervention in this document is editing a planning doc before code is written. If GraphEditorNode/GraphSerializer ship with raw handles, throw-on-error, and no string addressing, the mod API gets rebuilt later on top of a freshly-shipped internal tool — the most expensive possible order.
3. **The render-target migration touches every recording node.** Slot-type changes across ~10 node configs plus both graph factories. Mitigation: the `IRenderTarget`-shaped bundle mimicking `SwapChainPublicVariables` (which already has the conversion operators) lets nodes migrate incrementally; the benchmark suite is the regression harness.
4. **Hidden single-view assumptions beyond the audited ones.** Frame sync is hand-routed per node (15+ slots); per-view subgraphs multiply that wiring. Round 2 confirmed the worst case: each submitting node waits/signals the frame's single binary semaphore pair, so only one submitting pass per frame composes today (§5.2). The audit flagged it; the real cost surfaces only when the second view is wired. Budget for a graph-managed sync pass earlier than Phase 2's plan if minimap wiring fights back.
5. **Voxel-stack scale ceilings interact.** 15-bit pointers bind first (~32K descriptors), then bricks/axis, then Morton range. The multi-volume strategy sidesteps them but adds a composition layer that doesn't exist; if that layer slips, incremental growth within a single volume corrupts silently (until the Phase-0 assert lands).
6. **Two-front maintenance during transition.** The research/benchmark workflows (SIGGRAPH workstream) must keep running while the same subsystems are restructured. The benchmark suite doubles as the regression net — keep it green; it is also the only consumer exercising several paths (fragment pipeline, headless bring-up) the main app does not.
7. **Licensing ambiguity.** Repo root is MIT, but Sprint-6 headers carry GPL-3.0 notices and spread by copy-paste. Zero engineering, real legal exposure for a consumable library; resolve in Phase 0.
8. **Latent concurrency debt.** The TypedCacher deadlock, racy `VoxelInjectionQueue`, unsynchronized `mortonIndex`/block cache, and the re-entrancy-unsafe bus dispatch are all currently masked by single-threaded usage. Phase 3 unmasks every one of them at once; the Phase-0 fixes and a deliberate threading review before Phase 3 are the mitigation.

### Open questions (not resolvable from the audit data)

1. **Terrain representation:** is Undertow's world voxel-native (the research stack continues as the terrain engine) or heightmap/mesh with voxels as a feature? This gates Phase 3's largest line items and the multi-volume design.
2. **Scale targets:** concrete entity counts, world extents, and label counts for Undertow v1. "Hundreds-to-thousands of units" vs "1M markers" puts the instancing/indirect/culling work in different phases.
3. **Script runtime choice** (Lua, wasm, C#-host, none-at-launch): affects how strictly Layer 3's POD-boundary constraint must be enforced in Layers 1–2, and whether the command layer needs synchronous replies.
4. **Mod trust model at launch:** curated first-party packages only, or arbitrary third-party from day one? Determines whether Phase 5's sandboxing moves earlier.
5. **Multi-window requirements:** does Undertow need detached OS windows (editor/tooling), or only multiple views in one window? The static capability state and single-surface assumptions are cheap to fix for the latter, expensive for the former.
6. **The research workstream's fate:** does the SIGGRAPH paper trajectory continue in parallel (constraining how aggressively the voxel stack can be restructured), or conclude first?
7. **Undertow's sim tick architecture:** tick rate, threading model, and whether the sim runs in the same process — determines the sim-bridge journal's flush cadence and whether the bus needs cross-thread command queues earlier than planned.
8. **Where the game's own ECS lives:** extend GaiaVoxelWorld's vocabulary to non-voxel entities, or a separate sim-side ECS with a render-proxy bridge? The audit shows the current layer is voxel-only and compile-time-closed; the answer shapes whether GaiaArchetypes is consolidated or retired.
9. **Galaxy-scale numeric precision:** §2.3 requires a precision strategy (camera-relative coordinates, depth precision) that survives 4+ orders of magnitude of zoom, and no gap entry or roadmap item resolves it from the audit. Phase 2's camera-relative `CameraData` convention covers the camera half; the world half interacts directly with decision #5 (per-volume transforms make camera-relative rendering natural) and with Core's Morton ±2²⁰/axis ceiling — and needs the concrete extent targets of question #2 before the multi-volume composition layer is designed.
