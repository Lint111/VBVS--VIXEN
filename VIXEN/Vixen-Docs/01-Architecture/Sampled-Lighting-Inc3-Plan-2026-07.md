## The two prerequisites — and a KEY correction the scout surfaced

**KI-018's "3-hazard-slot cap" was MISFRAMED — this de-risks the increment.** The 3 slots in `ComputeStageNodeConfig` (`BUFFER_WRITE`@14, `BUFFER_READ_A`@15, `BUFFER_READ_B`@16, ConfigHeader :204-236) are AUTO-SYNC hazard-tracking slots (what the barrier baker reads to bake write→read edges), NOT descriptor bindings. The march already binds ~21 SSBOs/images via a SEPARATE `DescriptorResourceGathererNode` (`BuildRenderGraph.cpp` :1442-1631) — descriptor binding is fully decoupled from sync slots. So a separate lighting pass can BIND any number of buffers regardless of the "3-slot" figure. The scene SSBOs (octree/brick/instance) are READ-ONLY in both the march and the lighting pass → read-read is not a hazard → they don't even need sync-slot declaration. **The real KI-018 work:** the march runs on `ComputeDispatchNode` (swapchain-specific, no producer/consumer chaining); the fix is a new `DirectLightingNode` on `ComputeStageNode` (the auto-sync P5b node that DOES chain via sync slots + timeline edges, proven by VIXEN_FANIN_DEMO), declaring only the GENUINE hazards (HitRecord read, reservoir ping-pong, output write). If that's >3 hazard buffers (HitRecord-read + reservoir-prev-read + reservoir-curr-write + output-write = 4), a ~20-line N-slot generalization of `ComputeStageNodeConfig` rides along — the scheduler is already count-agnostic (iterates `Resource*` timelines, not fixed slots), so blast radius is contained to the config + the slot-read loop.

**KI-023 is small + additive, and one buffer serves two consumers.** M4's color-consistency reject (`|history.rgb - outColor| ≤ 0.15`, `BodyInstanceRayMarch.comp` :1471-1473) fights ReSTIR's noise (a converged history legitimately differs from a noisy current sample). Fix: a companion persistent worldPos/depth history image (mirror `AccumulationHistoryNode`/@20, new @binding-22, rgba32f = worldPos.xyz + depth.w), written each frame alongside the color history; the reproject branch loads it and rejects on GEOMETRIC disagreement (`length(histWorldPos - bestWorldPos) > ε` = true disocclusion, noise-invariant) instead of color. `bestWorldPos`/`hitT` are already in-register. **This same worldPos/depth buffer serves BOTH** Inc2's geometric reject AND ReSTIR's reservoir-reprojection validity — build once, two consumers.

**Interaction:** the intended stack is ReSTIR (noisy per-frame DI) → Inc2 temporal accumulation (EWMA) → tonemap. So KI-023 IS a real prerequisite for the combined pipeline (the color-reject would fire on ReSTIR's noise). ReSTIR's OWN temporal reuse (reservoir reprojection) is separate new code carrying its own reservoir-validity test — which reuses the same geometric buffer.

> **M1 SECOND MID-FLIGHT DECISION (user 2026-07-11): add a generic `IMAGE_WRITE` sync slot to ComputeStageNode.** Wiring DirectLighting's own output-image write surfaced a DEEPER gap than the blit: `ComputeStageNode` can chain BUFFERS between passes (`BUFFER_WRITE`/`BUFFER_READ_A/B`) but has NO image equivalent — its only image-write path is `SWAPCHAIN_INFO`+`isConsumer=true`, which is INSEPARABLY tangled with WSI semantics (acquire-wait + renderComplete-signal + fence + forced PRESENT_SRC transition; verified in RecordComputeCommands/ExecuteImpl).
