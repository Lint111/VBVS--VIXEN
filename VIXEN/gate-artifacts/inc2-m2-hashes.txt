Gate 0: pre-existing reflection bug found + fixed en route
------------------------------------------------------------------------------
Wiring the first bare scalar `uint` push-constant field (pc.accumFrameCount, field 12) through
PushConstantGathererNode's generic ExtractTypedResource path (the CameraData/InputState field-
extraction shortcut most existing fields use never exercises this path) exposed a pre-existing
gap in SpirvReflector.cpp::ConvertType: the SPV_REFLECT_TYPE_FLAG_INT case always mapped to
SpirvTypeInfo::BaseType::Int regardless of SPIRV-Reflect's own signedness trait, so a scalar
`uint` field reflected identically to a scalar `int` field. ExtractTypedResource's type-dispatch
table keys on (baseType, vecSize, arraySize), so the mismatched (Int,1,0,0) key routed a real
uint32_t-typed Resource through ExtractResourceAs<int32_t>, and Resource::GetHandle<int32_t>()
threw std::bad_any_cast (std::any_cast<int32_t> on an any holding uint32_t) -- crashed
vixen_editor.exe's very first Execute (exit code -1). Root-cause fixed by checking
typeDesc->traits.numeric.scalar.signedness (0=unsigned) in ConvertType and emitting
BaseType::UInt when unsigned. Confirmed no regression: all 4 SDI-parity gtests (which read
struct offsets directly, not this packer path) still pass with identical output; instanceCount
(int32_t, field 10) and raySizeCoef/raySizeBias (float, fields 8/9) -- the pre-existing scalar
non-field-extraction connections -- still pack correctly (verified via the full live gate below,
Packed 96 bytes / 13/13 fields connected, zero extraction failures across every frame of every
run). File: VIXEN/libraries/ShaderManagement/src/SpirvReflector.cpp.

read/write, reset-on-motion) is proven correct and ready; the actual variance-reduction benefit
is deferred until Inc3 introduces per-frame sampling noise for it to average over.
