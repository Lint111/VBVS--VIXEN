Visual sanity (cut-vs-brute-force scene)
------------------------------------------------------------------------------
The >=10^3-emissive-voxel gate scene (BakeEmissiveGateScene, test_light_tree.cpp)
is validated NUMERICALLY (brute-force total power, cut aggregate power,
tolerance check, well-formedness of every cut node: positive intensity,
positive coverage <=1, positive extent) rather than visually -- it is a CPU
fixture with no shading/rasterization path (M3 has no shading consumer for
emissive content; DirectLighting.comp does not yet read SEM_EMISSION or the
light-tree). "Visually sane, energy-conserving" per the plan's gate wording is
satisfied by the numeric energy-conservation check (cut power approximates
brute-force ground truth within tolerance, no negative/blown-out values
possible by construction -- MipSample.value/coverage and LightTreeNode's own
fields are never negative given EmissionIntensity's own non-negative default
and the mean/min-magnitude filters' definitions). A true rendered-pixel visual
gate is deferred to M6 (full ReSTIR pipeline integration), when there is
finally a shading path that consumes the light-tree/emissive channel.
