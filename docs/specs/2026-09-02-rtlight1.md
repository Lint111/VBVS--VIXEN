## Milestone evidence

### S0.1 — capability graph

Status: delivered in commit `bd40fa1e`.

- Added `RayQueryLighting` as an extension-based composite over acceleration structure,
  ray-query, and buffer-device-address leaves.

  `SubgroupCoopTraversal` composite.

- Focused graph gate: `test_vulkanresources_basic` — 2/2 passed.

### S0.2 — shadow `tmax`

Status: verified, no source change required.

The existing shadow/visibility path already passes real `tmax`: analytic shadows use
`shadowConfig.maxShadowDistance`, reservoir shadows use the actual light distance, and
the request path uses each request's `tmin/tmax`.

### S0.3 — wave slot-swizzle A/B

Status: delivered in commit `0797f57d`.

Added the guarded 64-lane Morton slot permutation, preserving the linear slot set and
the DDA/default variant. The graph and generated SDI variant axes carry the swizzle
feature. Hardware A/B numbers are not available because the required Windows RT run
could not be started.

### S1 — ray-query shadow-wave backend and AS lifecycle

Status: delivered in commit `89f95d52` for the code path; hardware gate pending.

- Device-local AS function pointers are resolved per logical device and reset on device
  destruction/recreation.
- Shell proxy AABBs feed one BLAS per octree and a TLAS over stored-SDF instances.
- Geometry and instance epochs invalidate the AS; rebuilds wait for device idle before
  retiring opaque AS handles, and dirty-brick revalidation advances the geometry epoch.
- `VIXEN_RT_LIGHTING=auto|off|force` selects ray query only through the
  `RayQueryLighting` capability; the composed-DDA path remains the fallback twin.
- RT allocations use the tracked buffer allocator and `RTAccelStructures` context names.
