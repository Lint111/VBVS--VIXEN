# hudwire1 — HUD view wire repair report

Date: 2026-09-03
Lane: `lane-hudwire`

## Result

The merged `Hud` view now declares both embedded arrays as SoA, and the generated writer emits
the columnar `UTVA` layout consumed by `ViewWireReaderSoa`. The generated typed accessor now
exposes the merged inspect scalars (`inspectSelected`, `inspectName`, `inspectCause`).

## Root cause and fix

The kernel emitter already had the correct branch: `ViewWireFormat.EmitField` dispatches a
`StructArray` with `ViewLayout.Soa` to `EmitSoaBody`, which writes one contiguous column at a time
(string offsets/blob per column, fixed-width values contiguously). The existing
`ViewWriterEmitterTests.ToBuffer_Produces_Canonical_Soa_Bytes` test proves that branch.

`VIXEN/codegen/view-schemas/Hud.cs` was the outlier: both arrays explicitly used
`[ViewSection(Layout = ViewLayout.Aos)]`. Bodies/derived row schemas use SoA. Changing the two Hud
declarations to `ViewLayout.Soa` is therefore the emitter-input fix; no new wire vocabulary or
hand-written generated-code workaround was needed.

Because layout participates in `ViewVersionHash`, regeneration intentionally changed the Hud
version from `0x9D4ACFD2` to `0x886D047D`. Regenerated artifacts:

- `VIXEN/application/main/include/Generated/Hud.view.g.cs`
- `VIXEN/application/main/include/Generated/Hud.blob.g.h`
- `VIXEN/libraries/RenderGraph/assets/ui/hud.viewblob`
- `VIXEN/application/main/include/Generated/HudTypedAccessor.g.h`

## Adapter finding (not edited)

The split writer types in `VIXEN/codegen/view-schemas/UndertowFrameAdapter.cs` remain stale:
`UndertowHudFactionsViewWriter`, `UndertowHudEventsViewWriter`, `UndertowHudInspectViewWriter`,
and `UndertowBodiesViewWriter` are not generated by the merged `Hud` schema. The schema intent is
unambiguous: only `HudViewWriter` is the surviving merged writer. This adapter/producer follow-up
belongs to the undertow-side producer integration and was deliberately not changed in this lane.

Exact migration shape for the adapter owner:

```diff
- public static UndertowHudFactionsViewWriter HudFactions(IReadOnlyList<HudFactionView> factions)
- public static UndertowHudEventsViewWriter HudEvents(IReadOnlyList<HudEventView> events)
- public static UndertowHudInspectViewWriter HudInspect(HudInspectView el)
- public static UndertowBodiesViewWriter Bodies(IReadOnlyList<BodyView> bodies)
+ public static HudViewWriter Hud(
+     HudView hud,
+     IReadOnlyList<HudFactionView> factions,
+     IReadOnlyList<HudEventView> events,
+     HudInspectView inspect)
```

The replacement method must populate `HudViewWriter.factions` with
`HudViewWriter.HudFactionRow` (`name`, `grievance`, `focused`, `known`, `inLens`,
`recentChanged`), `HudViewWriter.events` with `HudViewWriter.HudEventRow` (`kind`, `tick`), and
the top-level `inspectSelected`, `inspectName`, and `inspectCause` fields, then call the merged
writer's `ToBuffer()`. The existing producer's transforms remain the owner-side responsibility;
this report intentionally does not edit undertow producer code.
