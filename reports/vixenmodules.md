### PhotonCells consumer check and exact gap

PhotonCellTable has deposit/fold/clear consumers. BuildRenderGraph.cpp:9189 registers it in local sceneProviders, but a source/shader search finds no shading pass that reads PhotonCellTable; SpatialReuseShade.comp reads reservoir and hit-accumulation inputs, not PhotonCells. The requested shading GI consumer does not exist today.

A direct wiring sketch adds a read-only PhotonCellTable member to shading and applies sceneProviders.Provide("PhotonCellTable", ...). That meets immediate table-as-GI-input wiring but makes core shading name the module's table/schema. The isolated shape uses a Photon-owned resolve node to read PhotonCellTable and publish common IndirectRadiance/GIContribution; core shading consumes that semantic slot without naming PhotonCells.

**STOP / exact seam gap:** the registry registers node types but does not let a linked module contribute graph instances, passes, or providers to BuildRenderGraph. SdiProviderRegistry is local and hand-filled; it routes an existing source to a shader member but has no module contribution point or common GI contract. Registry/provider slots alone cannot express the clean optional-module path. R491 asks for no new mechanism; this graph-contribution/semantic-output boundary needs owner direction before phase 2. Direct table wiring is possible only by making core name PhotonCells internals.
