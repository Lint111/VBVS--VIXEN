## B6: any-hit recipe march

### What changed

`traceUberRecipeBody` (`VIXEN/shaders/SdfRecipes.glsl`) is the hand-written sphere-march every
recipe ray uses; only the field it calls (`evalRecipeField`) is generated by the kernel's recipe
GPU service. The shadow wave (`ShadowVisibilityWave.comp`) and `TraceWorldShadowImpl`
(`TraceWorld.glsl`) are hand-written passes too, so B6 is a hand edit and **the kernel is
unchanged** (no generated pass or generator is involved; the field text is identical).

- `traceUberRecipeBodyImpl(..., bool occlusionOnly, ...)` holds the march. With `occlusionOnly` the
  step sequence, the refinement bracket and `hitT` are the same instructions as before; only the
  six-evaluation central-difference gradient and the material evaluation at the certified hit are
  skipped. Two forms: `traceUberRecipeBody` (nearest hit: camera and probe rays) and
  `traceUberRecipeBodyAnyHit` (visibility rays).
- Callers: `TraceWorldShadowImpl` (through `traceRecipeChunks`, which takes the flag) and the
  ray-query any-hit twin `traverseRayQueryWorldAnyHit` (`RayQueryTraversal.glsl`). Both read only
  hit and distance. The shadow loop no longer transforms the normal it never read.
- The global `g_recipeProvenStepOnly` is deleted: it was `true` only around exactly these two
  any-hit calls, so the parameter carries the same relaxed-step rule.
- `g_lastRecipeMaterialId` is read only after nearest-hit traces, never after a shadow trace.
- CPU parity: `TraceWorldShadowMirror` (`test_traceworld_mirror.cpp`) models occluders abstractly
  and has no recipe march or gradient; the CPU march oracles of the bucketed-dispatch tests mirror
  the primary march, which is unchanged. No CPU face to change.
